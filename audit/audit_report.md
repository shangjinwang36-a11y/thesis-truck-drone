## 0. 结论摘要

1. **没有发现"代码把跨车接机整体压没"的单点 bug。** 50 客户上，穷举全部接机方案后，跨车方案被拒绝的原因 99% 以上是能量（充电 LP 无解 / SWAP_CANNOT_FIX），其余是 H 超限。手算复核成立（§1）。
2. **"跨车只占 0.7–4.5%"是指标口径问题，不是抑制证据。** 分母"全部回收 R"含大量例行回收（永远同车）。只看"失败触发的回收"，X 选跨车的比例是：规范配置约 18%，轻型约 13%，GH200 L1 约 43%，L2 约 23%（S 恒为 0）。论文请用这个口径。
3. **真实缺陷**（按严重度）：
   - H1 重规划时刻"级联顺延"，偏离规范。它是 200 客户 STOPPED 的主因。
   - H2 NO_FRAGMENT 幽灵航次 bug。
   - H3 STOPPED 对从统计剔除，造成对 X 不利的选择偏差。
   - H4 接机候选漏掉最优跨车方案，单事件最多漏 12 元。
   - M1 S/X 的 ALNS 随机性大于跨车价值，X 比 S 差的全是搜索噪声。
   - M2 切断窗口内的失败不被观察。
   - M3 退火温度尺度含历史前缀。
   - M4 保管清理只清别车，导致原车方案被误拒。
   - L 若干（§5）。
4. **GH200 的 STOPPED 不是真实不可行，主要是代码问题。** 只去掉级联顺延（`AUDIT_NOCASCADE=1`）并修 NO_FRAGMENT（`AUDIT_FIXGHOST=1`），重跑 L1 的 7 个 STOPPED 里的 7 个（仅首次失败）：5 个 S、X 都 COMPLETED_VERIFIED；其余 2 个（C200 seed 3、RC200 seed 6）S 仍无解而 X 完成，属于真实的 S 无解（边界，C200 seed 3 只差 0.01 kWh）。
5. 平均差距的期望：修了之后**不会到几百元**。单次失败事件穷举的最大节省是 11.8–29.7 元，班次总成本 200–1400 元。钳制 X≤S 的上界见 §4 表。

### H4（中高）候选生成漏掉最优跨车方案
**证据。**

- 规范自然 RC50 seed 3：oracle 432.9，代码 435.1。
- 轻型自然 C50 seed 5：oracle 222.4，代码 224.3。

**原因。**
- (a) `recovery_milp.py` 代理成本只计接机卡车的绕行与 R/U 工时，不含"原放飞车不用再赶到回收点、提前收班"的节省，而这是跨车的主要收益。`milpchk.py` 显示 top-6 全是同车方案，且既有访问与同地点的支援访问重复占用 top-K。
- (b) `recovery.py::_entries_est` 的继续子集只有 空/单票/全集/（≤4 票时的两两组合）。规范配置每航次 6–9 票，oracle 最优常是"前 k 票"，不在目录内。

**修复。**
- MILP 目标加"原放飞车路线缩短"项，或改为"每车各取前 K 个"送完整评价；
- top-K 去重；
- 目录子集加入全部前缀子集。

**对 S−X 的预期。** 只影响 X。规范配置有利事件约 1/4，漏掉的 5 个例子里节省差 1.9–12.4 元，所以均值约 +0.3~1 元（规范 C50 类），属估计，需修复后实测。

### H2（高）NO_FRAGMENT 是代码 bug，已验证修复
`simulate.py:364-367`：`for sid in plan.drone_sorties[d]: if sid in inflight: cur = sid` 取"最后一个在飞"的航次。失败机在旧计划里之后的航次（幽灵：失败机其实在原地悬停）一旦因 t_cut 过大被当成"已放飞在飞"，就覆盖了 cur。真正的失败航次被当成已完成并从机体链弹出，`initial_recovery` 找不到 frag，报 NO_FRAGMENT。

证据：L1 C200 seed 2 和 seed 8（t_cut−t_fail=243.9 s，首层 22.1 s，`frag_present=False`）；L2 的 C200 seed 6、R200 seed 3、R200 seed 10。副本修复（失败机强制 `cur=failed_sid`）后 L1 的两个例子完成。

### M4（中低）G_CUSTODY 误拒：只清别车的旧地送
`recovery.py:471-474` 清除移交票的旧地送时有 `v.truck != truck` 条件，同车残段里已预置的地送没清。新接机点晚于该访问时，评价器判 `G_CUSTODY holder=DRONE`（先送后接，确实非法），这是候选构造问题，把地送挪到新接机点之后即合法。

同车（S 与 X 共有）方案被误拒比例：规范自然 994/6189 = 16%，规范强制 1135/3503 = 32%，轻型自然 62/2254，轻型强制 166/3524。副本取消 `v.truck != truck` 限制后（`AUDIT_FIXCUST=1`），该类拒绝消失，最优成本平均只降约 0.12 元，S 与 X 同样降。**对 S−X 无影响。**

### L1（低）validate_structure 不检查同机航次顺序（链路成环，未重新证实）
`plan.py:160-239 validate_structure` 只核对承运车一致，不核对"同机后一航次放飞访问不得早于前一航次回收访问"。我在 GH200 RC200 L1 seed 6 的候选重放中曾观察到成环的时间链（调度迭代不收敛，被判 H_EXCEEDED），脚本为 `gh_rc6b.py`，最终报告前未重新复现，请当作线索核对。修复建议：在校验里加路线次序检查。

## 6. 确认正确的部分
- 失败生成器；SHA256 种子与排序；M∈{1,2}。
- 成本口径：里程、工时、电费（手算复核）。
- S/X 资格：S 只用 `launch_truck`，X 全部在班卡车。
- 未出库/已收班车辆不被启用（规范 4.3）。
- 评价预算对等。
- 能量/等待上界：负余量不会被截成 0（SWAP_CANNOT_FIX 带负号输出）。
- 信息隔离。
