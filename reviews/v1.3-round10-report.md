## What changed inside X

Three pieces, all inside X’s loop.

1. **Uncharged scheduler delta, then a charged evaluation only if plain J can improve.** A cross proposal still has to clear the real scheduler (swap, charging, H, slots, channels, `E_min`, and the cross floor) before it is a candidate. That check is not an evaluation. The same timeline is then priced: truck distance, driver time including waits, depot refill, and the v1.3 failure terms. `eval_counted` runs only when that J beats the best plain J already stored. Every charged cross in this run was feasible, and every one of them beat that J at the time it was charged. A cross that wins is stored in the best-J archive. It is not written into the same-truck incumbent, so the destroy and repair path does not follow it.

2. **Adaptive cross share.** The roulette is `SKIP`, `MULTI`, `RELIEVE`, `RETARGET`, and `PAIR`, on X’s own random stream. A charged cross that does not beat J cuts that kind’s weight to a quarter (floor 0.02) and adds 2 to `SKIP`. An accept adds 4 to the kind. The segment update is the same reaction, 0.2, that S uses for destroy and repair. On the maps where no cross survives, the charged share of the 1000 is 0 to 0.6%.

3. **The periodic scenario-cache fill no longer buys extra evaluations for X.** That fill is not an acceptance test. With cross recourse turned on, X kept charging scenario repairs after S’s same-truck recourse had already stopped. Those extra charges, not a published cross, were the whole of RC50’s nominal gap (0.14 yuan) and the significant episode loss in an earlier build of this round. X now fills that cache with the same same-truck recourse S uses. RC50’s published plan is byte-identical to S, and its 19 paired episodes are exact ties.
