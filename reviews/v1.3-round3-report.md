# v1.3 round 3

Same branch and the same pull request as rounds 1 and 2. Test seeds 4001–4030 were not used. Tune is seeds 101–110. Dev is seeds 1–10. The run is `r6/results/v13_round3_full` (tune) and `r6/results/v13_round3_dev`. Ablations are tune only.

## Hard constraints

- [x] **No 0.2 failure weight, for S or for X.** Under `v13_rules`, `failure_prob` returns `3/(2N)` and does not read `scenario_p` or a stored 0.2. `expected_j(..., v13=True)` uses `3/(2N)` on the single terms and `1/(N(N−1))` on the pair terms and ignores the `p` argument. The old default that filled a missing probability with 0.2 is gone (`scenario_p` now defaults to 0, and the v1.3 branch never consults it). `tests/test_v13_acceptance.py::test_planner_does_not_read_point_two_failure_weight` builds a planner whose `scenario_p` raises if it is read, and checks that a poisoned `p=0.2` does not change the v1.3 objective. The section-12 suite is 14 passed.
- [x] **No “S first, then X”.** The round-2 two-phase nominal (same-truck slice, then a cross tail, then a phase-1 champion gate) is deleted. The recovery stagnation hand-off is deleted: X does not run S’s recovery and then a second cross search. There is no 40-iteration stop. X’s nominal search and X’s recovery are each one loop on X’s own 1000 evaluations. Same-truck repairs and cross-truck operators are both in that loop from the first iteration. A cross updates the champion only when v1.3 J improves, and it does not replace the plan the same-truck operators are still searching.
- [x] **No experiment setting was changed.** Rules v1.3, the failure model, the probabilities, the budgets (1000 nominal, 1000 per recovery process, 60 s), the seeds, the fleet, the energy model, H, the prices, the statistics, and S’s operators are the ones from round 1. S’s only change is the shared weight bugfix above. Ideas that would need a setting change are listed at the end and were not implemented.

## What changed in the search

S and X both accept a nominal move by v1.3 J. S’s neighbourhood is still same-truck only. X adds, inside the same loop and the same 1000:

- Cross-truck recovery construction. At a failure, X enumerates a rendezvous with every other truck the loaded drone can still reach, and re-sequences the drone’s later tasks. Those entries sit in the one recovery catalog.
- Catalog order for X. Rescue entries are ranked by estimated truck-detour saving, then the remaining same-truck and cross-truck entries are in estimated-cost order. S’s catalog order is unchanged.
- Nominal cross operators already in the code (convert a same-truck recovery onto another truck, a support rendezvous, and an energy retarget of a tight cross), called on their existing period from the first iteration. They are accepted only when v1.3 J improves on the champion. The shared repair list stays same-truck, so a cross proposal does not throw away the same-truck candidate in that iteration.

The 0.08333 kWh nominal cross margin and the 90 s rendezvous slack are the existing X gates. They were not retuned.

## Proposals that were not implemented

- Replace the search proxy for `Q_i` and `I_ij` with the 20 training scenarios (`J_hat`) on every acceptance. The coefficients would stay `3/(2N)` and `1/(N(N−1))`. Each comparison would spend many of the 1000 evaluations, so this is a search-design change with a real budget consequence and it was not turned on.
- Give X a larger nominal budget so the cross proposals on R50 and R100 do not displace same-truck improvements. The cap stays 1000.
- Relax H, the 0.08333 kWh cross margin, or the failure model to lift RC50’s completion. Those stay as specified.
