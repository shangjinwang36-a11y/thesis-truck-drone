Same branch and the same pull request. Test seeds 4001–4030 were not used. Tune is 101–110. Dev is 1–10. The main run is `r6/results/v13_round8`. Acceptance tests: 15 passed.

X is one integrated search. From iteration 1, a cross kind or `SKIP` is chosen inside the same loop as the same-truck repair. There is no second phase.

## Hard constraints

- [x] **No 0.2 failure weight, for S or for X.** Planning uses `3/(2N)` and `1/(N(N−1))`. `weight_reaction = 0.2` is the ALNS operator-weight reaction, not a failure weight.
- [x] **X is one integrated search.** Common random numbers reseed the same-truck stream at every iteration. They do not run S to completion and then start X.
- [x] **No experiment setting was changed** in the main run. Rules, failure model, probabilities, budgets (1000 / 1000 / 60 s), seeds, fleet, energy, H, prices, statistics, and the 0.08333 kWh margin are unchanged. The 10× budget in the ceiling section is diagnostic only and is not a main result.
- [x] **Equal treatment of the random stream.** Destroy, repair, and acceptance draws are reseeded with the same formula for S and X. The cross stream is a second generator that S does not have.

## Scheduler mismatch

On R50 in round 7, 15 of 18 floor-legal meetings were infeasible on the real schedule. The geometric check prices only the edited sortie: flight, wait from the truck-only clock, plus launch, one service, and recovery. The failures were `SWAP_CANNOT_FIX` on a **different** drone. Moving the recovery visit changes that truck’s arrival times, another drone waits longer, and a fresh battery at its own launch is not enough.

The pre-check now runs `schedule_plan` (swap pass, charging, H, slots, channels, and the 0.08333 kWh floor) and does not charge a search evaluation. A meeting the scheduler rejects is not returned. In this run every cross that was evaluated was feasible: C50 15/15, R50 9/9, RC50 12/12, C100 37/37, R100 21/21, RC100 18/18. The scheduler rejected, for free, 1, 2, 6, 29, 4, and 10 bundles on those maps.
