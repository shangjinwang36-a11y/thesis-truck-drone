# 代码审计报告（第 5 轮开始前）

时间：2026-11-13。对象是当前 `proj_r6` 里的 truck–drone 模型与 S/X 求解器。这一轮在加任何新算子之前做完。评价种子 1–10 只用来核对，不用来改规则。

## 结论

**没有发现会改变报告成本或回合状态的模型错误。** 评价种子 1–10 的 60 对用当前代码重放，状态和成本与第 4 轮已发表的 `r6/results/round4/episodes.json` 逐对相同（绝对差阈值 1e-6，差的个数为 0）。

完成回合 99 个（S 47、X 52）全部通过不变量：电量不为负、同一无人机的阶段不重叠、机位与通道不超限、每个客户恰好交付一次、回放成本与评价器成本之差不超过 1e-4、S 的跨车次数为 0。

停止回合 21 个在补上“停止时保留已执行前缀”之后也全部通过同一套不变量（未送完的客户允许还留着）。S 的这 13 个前缀里跨车回收次数为 0。

因此第 4 轮公布的 C_res、Δ 和完成/停止状态仍然有效。下面几处修复改的是检查器和日志，不改搜索得到的成本。

## 1. 仿真 / 回放与规划器是否一致

核对了时间、能量、承运车、机位、换电。

- 名义解 12 份（第 3 轮 R3，6 个案例 × S/X）都可行，调度在 22 次迭代上限之内收敛，回放违规为空，回放成本与 `evaluate_plan` 之差 ≤ 1e-4。S 的名义成本与第 3 轮常数一致：C50 178.14587164120755、R50 453.657285906743、RC50 354.0172081754592、C100 458.68341394196545、R100 732.355091852888、RC100 679.490167646717。
- 换电模式下 `c_vehicle` 乘的是车载交流充电量。这条量在换电路径里是 0，仓库补的是换下来的电池，S 和 X 用同一个公式。独立 `verify_plan` 在改成同一公式之后，12 份名义成本与评价器一致。
- 完成回合的执行日志走 `verify_replay`：里程、司机工时、换电补电、入库余电重算出来的成本与最终评价一致（60 对里成本差的个数为 0）。负电量、回收结束低于备用电量、同一无人机阶段重叠、同一票交付两次，在这些日志里都没有出现。
- 机位：规划器按“回收开始预留、放飞结束才释放”做区间扫描，计划被接受之前已经查过。回放在每次回收动作上再数一次当时在车的机体。两套都通过。
- 换电 60 s、备用电池块数、载荷 4 kg 写在 `package_light.json`，回放会拒绝时长不对的换电、备用块用尽、以及超载（结构校验）。

已执行回合的检查在 `src/tdr/invariants.py` 的 `check_episode`。测试在 `tests/test_invariants_audit.py`。全量重放脚本是 `r6/audit_episodes.py`，停止回合的补查是 `r6/audit_stopped.py`。结果：`r6/results/round5_audit/audit.json`、`stopped.json`。

## 2. S 从不跨车，X 多出来的只有跨车资格

S 的跨车入口都关着，而且执行日志里实际为 0：

- 名义：`cross_launch=False`，阶段 2 不打开跨车候选。生成结束后断言 S 名义没有跨车航次。12 份里 S 的跨车数为 0，X 只在 R50（3 条）和 RC50（1 条）有跨车，其余四个案例 X 采用了 S 的名义解。
- 恢复目录：S 的候选卡车只有原放飞车（`RecoveryCatalog`、MILP 的 `build_stops`、残段候选、未起飞航次改回收点）。测试锁了“S 的目录卡车集合等于放飞车”。
- 通用修复里的新航次：`allow_cross` 默认关，恢复状态的 `nominal_cross` 是 False。跨车新航次只在 X 的名义阶段和再飞算子里打开。
- `cross_ops.cross_pair` 在放飞车等于接机车时返回空，S 不消耗评价。再飞算子在策略不是 X 时不产生候选。
- 已起飞残段改派后，`truck` 字段会被写成接机车，原放飞车留在 `launch_truck`。`is_cross_sortie` 故意不计残段，避免把已经发生的放飞再送进名义图。审计用 `recovery_is_cross`：残段比较 `launch_truck` 和回收车。完成回合和停止前缀里，S 的这个计数都是 0。回放对 S 的回收动作再查一次 `launch_truck != actor`，同样为 0。

X 相对 S 多出来的物理资格是：失败航次和名义航次可以由另一辆合格卡车回收，后续未起飞航次改从这辆回收车放飞。下面第 5 节里的再飞、风险价和“不新开空送”是搜索规则，不改写进结果的 C_res，也不是第二套物理。

## 3. 成本核算对 S 和 X 相同

`evaluate_plan` 没有策略参数。词典序是先 C_res 再 z（`_better`），容差沿用算法配置。风险价和新开空送惩罚只包在 `_better_air` 的比较对象上，不改 `ev.cost`。`soft_h` 在 light 配置里是关的，所以没有加班费。换电配置下车辆充电费为 0，仓库补电费两边一样计。

完成回合上，回放成本与评价成本之差没有超过 1e-4 的。

## 4. 失败抽样在共同随机数下对 S 和 X 相同

伯努利标记是 SHA256(`[版本, "bernoulli", 案例, 种子, 包裹]`)，没有策略，也没有把 p 放进哈希（不同 p 的失败集合嵌套）。每个回合用同一组隐藏集合建两个世界，一边一个。60 对重放里，S 与 X 读到的隐藏集合和独立函数算出来的集合全部一致。

## 5. 第 3 / 4 轮规则是不是把模型改坏了

这些规则都只收紧 X 的搜索或发布，不改 S，不改成本公式。

- **X 的名义完工时刻不超过 S。** 评价用的 H 是 H_S = S 的完工时刻 + 1800 s，两边相同。若 X 的名义比 S 长，它会先吃掉这段松弛，失败之后更容易越过 H。发布时若 X 越过 S 的完工时刻，或名义成本更差，就改用 S 的名义解。搜索过程中的上限是 max(阶段 1 完工, S 的完工)，避免阶段 1 自己已经被判越限、跨车移动全部消失；最终写出去的计划仍须不超过 S。已发布的 6 个 X 名义全部满足。这是公平约束，不是改物理。
- **恢复时 X 的通用修复不新开空送。** 规范允许在物理和剩余需求之下新开空送。代码在 `x_new_air_penalty = 0` 时对 X 的通用修复仍是硬禁止；S 没有这条禁止。第 4 轮曾把硬禁止拿掉，C50 变差，所以又加回去。这是对 X 的额外搜索限制，不是额外能力。再飞算子是唯一还能提出一票新空送的 X 路径，接受时加上 p ×（地面插入代理 + 一次回收工资），写进结果的仍是真实 C_res。它会先试同车，不够再试别的合格卡车，所以不完全是“只多了跨车”，但是它不改变报告成本，也不给 S 少算预算。
- **跨车之后的后续航次从实际回收车放飞。** 无人机人已经在回收车上，下一趟不能再从原来的放飞车起飞。链如果断了，会另给一份把断掉的航次改地面的候选，已经可行的候选仍先保留。S 和 X 的结构校验用同一套承运链。
- **新跨车航次要多留 5% 电量裕度。** 只拒绝刚刚够到 E_min 的新跨车或改了回收点的跨车，不改存储成本，S 不走这条。

初始化预算 100 与主循环 1000 分开，S/X 相同。联合重选最多再加 60 次，降落等待或未起飞修复再加 120 次，重建兜底再加 24 次。这些常数对 S 和 X 一样，不是单方面加预算。

## 6. STOPPED_NO_FEASIBLE_SUFFIX 和 H_EXCEEDED 是算错了还是真的不可行

第 4 轮的停止全部是 `INITIAL_RECOVERY_FAILED`，笔记里是 `H_EXCEEDED` 和/或 `SWAP_CANNOT_FIX`。没有 `SLOT_OVER`，没有 `MAX_REPLANS`，没有 `INVALID_EXECUTION`。重放之后状态集合不变：S 停 13、X 停 8。

- **H_EXCEEDED** 是卡车返库时刻超过 H_S。超出从约 8 s（R50 种子 3 的 X：t4 在 6033.7 s，H_S 为 6025.8 s）到一千多秒。调度器每次把卡车和无人机各排一遍，换电配置下上限是 22 次。有环的跨车等待在进入调度之前就被 `CROSS_WAIT_CYCLE` 拒绝。无环时信息沿依赖传递，已发表名义解都在 few 次迭代内收敛。本轮把“未收敛”从“只在有跨车航次时拒绝”改成“任何未收敛的时刻表都不可行”，60 对的状态和成本没有变化，说明这 60 对里被选中的计划本来就是不动点。8 秒那次是被拒绝的候选，不是一份被当成可行成本公布的错误时刻表。
- **SWAP_CANNOT_FIX** 是换上满电电池之后，回收结束仍低于备用电量 0.05 kWh，或电量已经为负。近失的例子（R50 种子 6 的 X）是未起飞航次 d7 在 3936.9 s 处余电 0.0428，差约 0.007 kWh，大约 20 秒空载悬停，不是把 30 秒回收悬停算了两次。丢掉该航次的最后一票，失败会挪到另一架机体上。这是名义航次在额外等待之后能量真的不够，加上邻域没有把每一架都修到可行，不是时钟没收敛。
- 降落等待（`land_and_wait`）只给已经起飞的残段生成“落地后零能耗、回收不要求 E_min”的候选。未起飞、满电仍差 0.007 kWh 的航次不会走这条豁免。这是搜索邻域没覆盖一种已允许的动作，不是执行器把电量算错。本轮没有为了减少 STOPPED 去加这个候选。那是新功能，要单独在调参种子上量过再决定。

## 发现的问题、修复、以及结果变了没有

| 问题 | 修复 | 对第 4 轮 60 对的影响 |
|---|---|---|
| 停止或中途失败时，已执行的前缀只留在局部变量里，`ep.segments` 仍是空的。不变量看不到这段飞行，`n_fail_rec` / `n_fail_cross` 被记成 0 | `run_episode` 在所有出口保存 `segments` | 状态和成本不变（补查 21 个停止侧，差为 0）。停止侧合计补回 128 次失败回收，其中 X 有 5 次跨车（R50 种子 3 为 1，RC50 种子 9 为 1，RC100 种子 9 为 3），S 仍为 0。全样本 X 的 `n_fail_cross` 合计从 69 改为 74，均值从 1.15 改为 1.23。第 4 轮报告里“完成对上均值 1.34”只统计了当时有日志的完成回合，那个句子不用改 |
| 未收敛的时刻表只在存在跨车航次时拒绝。同车长链可能带着一个还在变的时刻表被接受，或被误记成 H_EXCEEDED | 任何未收敛都记为 `SCHEDULE_NOT_CONVERGED` | 这 60 对的状态和成本没有变化 |
| 同车航次的放飞访问不早于回收访问时，时刻成环，以前结构校验放行 | `validate_structure` 拒绝 | 已发布名义解没有这种航次。这 60 对的状态和成本没有变化 |
| 回放不查负电量、回收结束备用电量、重复空送、未排序的通道区间、同一无人机阶段重叠，也不查 S 的跨车回收 | `verify_replay` 补上这些，回合把策略传进去 | 完成回合和停止前缀全部通过，没有把 `COMPLETED_VERIFIED` 改成 `INVALID_EXECUTION` |
| `verify_plan` 用了另一套车辆充电费公式，S 的策略检查看的是改派后的 `truck` 而不是 `launch_truck`，降落等待的回收仍要求 E_min，也不查机位、通道和是否收敛 | 与 `evaluate_plan` 对齐，名义核验传入 S 或 X | 不参与搜索。12 份名义成本与评价器一致，S 的跨车数仍为 0 |
| 回合结束时的 `n_cross_final` 用 `is_cross_sortie`，已起飞且被改派的残段被漏计 | 改为 `recovery_is_cross` | 不改搜索，不改 C_res。下一次写出的指标会把残段算进去 |
| `RecoveryCatalog` 里有一段算了但没有用的 `trucks_ok` | 删除 | 行为不变。S 仍只保留放飞车的条目 |
| 运行脚本的注释把第 4 轮写成“硬禁止已经关掉” | 改回：惩罚为 0 时硬禁止仍在，风险价只约束再飞算子那一票 | 不改行为 |

以后每加一个功能，都要有对应的不变量或单元测试，并且在调参种子上量过，再决定要不要进唯一的那一次正式评价。
