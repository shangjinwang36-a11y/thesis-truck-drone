## 1. 跨车回收修复（`recovery.py: build_residual_candidate`）
- 原因：失败票由机上"交接"给接机车时，残段底板里这些票在**别的车（通常是原放飞车）**上遗留的旧地送安排没有清除，
  导致货物保管冲突 `G_CUSTODY`，所有跨车候选一律不可行 → X 实际上从未真正用过跨车回收。
- 修复：构造候选时，把交接票从其他车辆访问的 `ground` 中清除。
- 回归测试：`test_cross_truck_candidates_have_unique_custody`（去掉修复这一行则该测试失败，已做变异验证）。

## 2. X 的恢复搜索覆盖 S（`recovery.py: RecoveryCatalog`）
- 候选条目按**估计成本**排序（复用 MILP 代理里的 stop/地送/能量估计），不再按距离排序。
- S 的候选序列（仅原放飞车）取前 `guard_n = (初始化预算-4)//2` 个，**保证全部放在 X 第一批评价里**，再接 X 自己的排序；S/X 初始化预算相同。
- 测试：`test_x_first_batch_contains_s_prefix`、`test_x_startup_not_worse_than_s_same_env`（同环境下 X 起点最优 ≤ S，预算 60/100 各一次）。

## 3. 成本驱动的"转空送"名义解构造 + ALNS 修正
- `nominal.py`：新增 `descent_pass`（逐票按"卡车绕行节省"排序，每票最多 3 个空送候选，用**完整评价**比较，新建航次时才多评几个 λ 起点），
  双起点（下降起点 vs 原块转换起点，各跑 150 评价的 ALNS 小段，择优后用剩余预算继续），总预算仍是 1000（下降 ≤200 内含）。
- `moves.py`：修复修复算子偏置——地送代理成本补上"绕行驾驶时间×工资"，空送代理补上同步等待成本；新增 `repair_air_first`。
- `alns.py`：新增 `GROUND_TO_AIR` 破坏算子 + `AIR_FIRST` 修复算子（"move-to-air"）；仅新建航次时才评多个 λ 起点；ALNS 内坐标细化改为轻量模式（复用已知评价，≤12 次）。
- 开关均在 `AlgorithmConfig`：`air_promote_ops / geometry_new_sortie_only / coordinate_light / nominal_descent / nominal_two_start ...`，设为 False 回到第一轮行为。

## 4. 多次失败下的无效/中止回合：确认为代码缺陷并已修复（`simulate.py`）
用强制失败 k=3/6 批量压测（`/workspace/thesis/diag/multi_fail.py`、`stress.sh`）复现并修复 6 类缺陷：
1. 截断点恰为回收结束(R末)而卸货 U 紧随其后 → U 未随本段完成，日志与回放保管者不一致（`SEGk_HOLDER`/`G_CUSTODY`）；截断点顺延改为不动点迭代，覆盖 G/P/R/U/L 内部。
2. 失败机在旧计划里的后续 P/L/R/U（"幽灵动作"）仍被记入执行日志/顺延截断点（`R_DRONE_NOT_THERE`）→ 失败揭示后一律忽略。
3. 失败机在旧计划里"之后的服务"被算成已交付（失败票之后的票被误记 DELIVERED）→ 忽略。
4. 失败揭示后到截断点之间，失败机应原地悬停；日志按旧计划 CRUISE/SERVICE 记能耗 → 改为带原载荷的悬停（`SEGk_ENERGY`）。
5. 同一时刻连续截断，空中残段首阶段为 WAIT 时丢失起始坐标 → "空中残段缺少起始坐标"导致 STOPPED。
6. 装机(P)已完成、放飞(L)未开始即遇截断，机上票没有经零时长 U 卸回 → `SEGk_HOLDER`。
- 另加兜底：残段/目录/MILP 均无可行解时，对前 12 个条目走"清空未来重建"，额外评价额度 S/X 相同（`REBUILD_FALLBACK`）。
- 回归测试：`test_multi_failure_episode_verified`（4 个场景 × S/X）。
- 仍存在的中止：极少数回合（主实验 1/60，S/X 同时）为"失败机剩余能量不足以在保留电量约束下被任一车接回"（例：R50 seed4 第2次失败后，最优候选仍差 0.02 kWh 储备），
  以及强制 6 次失败时初始化预算 150 不够（预算 600 即可完成），均不是代码错误，已在结果中如实计数。
