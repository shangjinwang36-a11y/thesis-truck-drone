# 晨间报告：卡车–无人机跨车接机（X）vs 同车接机（S）——第四轮全部工作

> 更新：用户已将**标准配置固定为 light2**（3 槽、2 架/车、换电；50 客户 5 车、100 客户 8 车），敏感性分析暂缓：light1 与少车场景已按指示停止，仅继续 light2 场景与 light2 事件分析（见 6.3、第 7 节）。

分支 round4；S=失败无人机只能由放飞车回收；X=任意合格卡车。所有实验同预算、同算法参数，无偏置/配额，全部回放核验，每次运行都入结果文件。

## 1. 一页结论
1. 代码里确实有多处真 bug（H1/H2/H4/M3/M4/L1 等，第 2 节），修复后 X 更差的情况大幅减少、STOPPED 不再单边，但**总体差距仍是 0.1–0.2% 量级**——这是模型的结构性结果，不是遗留 bug。
2. 我加了 RECOVERY_RETARGET 与三个 X 专用跨车算子，消融**无增益**；算法参数网格与 CRN 也**无稳定收益**。
3. 敏感性（失败数/池/资源/H 余量）下，总体 Δ/C_S 最高约 1%（原规范、池=空送、M=5），分算例最高 3.6%；**没有任何总体场景 ≥5%**。事件级（以跨车为条件）平均省 ≈6 元/≈1.5%，最大 5.2%。
4. 最诚实的论文叙事：X 可行域包含 S；跨车价值是条件性的，随失败集中度和资源紧张度上升（第 8、9 节）。

## 4. X 专用跨车算子与消融
- **RECOVERY_RETARGET**（在当前最优计划上重选接机车/点；S 只能原放飞车，X 可任意车；同频率同评价数）：forced M=3 消融 Δ/C_S：spec 1.42%→1.31%，light2 0.16%→0.12%，**无增益**。
- **X 专用 cross_ops**（`cross_ops.py`，仅当失败航次被≠原放飞车的车接回时才触发 → S 恒不触发；占用 X 同一份 1000 评价预算；无配额/惩罚）：
  LAUNCH_TRUCK_RELEASE（原放飞车不再等机后，K1/K2 剩余纯地面访问重新定位）、TRUCK_TASK_SWAP（K1/K2 互换地面访问）、FAILED_PARCEL_GROUND_REASSIGN（交接票在接机车上的地送位置重排）。
  消融（forced M=3，8 seeds×C50/R50/RC50）：spec 5.52→5.42（Δ/C_S 1.42%→1.39%）；light2 0.55→0.55（完全相同）；解除门控(S/X 都能用)spec 5.63、light2 0.68。主实验：spec 0.59→0.54，light2 0.45→0.43，light1 0.98→0.98。**无可测收益。**
- 原因：恢复阶段包裹保管链固定（车上的票只能由该车送，交接票只能由接机车送），"把别车的地面客户搬给另一辆车"几乎不可行；X 真正多出的自由度只有"选哪辆车接机"，已由 MILP/目录覆盖。
- 代码保留且默认关闭（`cross_ops`、`recovery_retarget`、`cross_ops_gate`），论文中可作"算子消融：专用算子无额外收益，优势来自接机车选择本身"的负结果。

所有场景：名义解固定（`nominal_r3fd1000`/`nominal_L1_1000`/`nominal_lightR1000`，少车用 `nominal_Lfew_1000`），恢复预算 1000，MILP 接机，S/X 同参数同预算，全部回放核验；每场景 60 个环境（6 算例×10 seed）；STOPPED 的对不剔除（单列），Δ 仅在 S、X 都完成的对上统计。

**各场景的现实依据**
| 参数 | 取值 | 现实依据与说明 |
|---|---|---|
| 失败数 M | 1–2（规范基线）、3、5 | 基线是规范的小概率设定；M=3/5 是压力情形，对应恶劣天气、小区临时封闭/门禁、停机坪被占等**失败高度相关**的日子。属敏感性分析，不替代主实验 |
| 失败候选池 | 全部客户（规范）/ 仅名义空送客户 | 规范中失败点在全部客户里抽，部分抽中的是地面送客户，不触发恢复，稀释失败数；"仅空送客户"是**以"无人机确实要去投递"为条件**的口径——等价于只看会发生恢复的那部分失败，是条件分析 |
| 每车无人机 | 1 架 vs 2 架（均 3 槽、换电、RA3 轻型机） | 1 架：资源紧；2 架：微卡货厢可容纳（迅蚁 RA3 折叠后三架可入五菱货厢）。用来检验"资源越紧，跨车越有价值" |
| 车队规模 | 50 客户 4 车/8 机、100 客户 6 车/12 机（对照 5/8 车） | 站点车辆紧张时每车负荷更重；可接机的"其他车"更少。验证跨车价值与可用车数的关系 |
| H 余量 | 1800 s（规范） vs 900 s | H=名义完工时间+余量；余量是班次缓冲（交接班、站点收班时限）。900 s 代表排班更紧的站点，恢复可行域更窄 |

## 7. 事件级条件分析（条件统计，不是总体平均）
**方法（明确为条件统计）**：对 X 回合里的每个失败事件，在**同一状态**（同一残余计划、同一快照、同一已失败集合）上再跑一次 S 的恢复（同参数、同 1000 评价预算、同随机流种子），事件节省 = 成本(S 恢复后的全班计划) − 成本(X 恢复后)。这样比较的是"同一时刻 S 与 X 各自能做出的最好恢复"，不受后续失败路径分叉影响。
- "X 选跨车的事件"=最终计划中失败航次由≠原放飞车的车接回；同车事件的节省理应≈0（仅搜索噪声）。
- 以下数字是**以发生了跨车恢复为条件**的，不是总体平均；总体平均见第 3、6 节。必须在论文里这样表述（"当跨车接机被采用时，每次平均节省…"），不能当作总体效果。
- 特征用 Spearman 秩相关 + 前 1/3/其余对比；样本量小时只作讨论线索。

## 8. 对 5% 目标的结论
**诚实结论：总体平均的 Δ/C_S 达不到 5%，在任何一个符合规范或有现实依据的总体场景里都没有；5% 只在"单个事件、且以发生跨车为条件"时偶尔出现。**
- 总体（60 个环境的配对平均）：规范主实验 0.13%，轻型 0.09–0.20%；加大失败压力后最高为 **池=仅空送客户、失败 5 次、原规范：1.15%**（分算例最高 C50 3.62%、RC50 2.90%）。完整榜单见 6.5 节（随敏感性队列完成更新）。
- 事件级（条件）：跨车事件的平均节省约 6.3 元，约占该班 C_S 的 1.5%；最大单事件 20.8 元（RC50 seed6，5.0%）、12.0 元（C50 seed5，5.2%）。**这是 20 个跨车事件里的最大值，不能当作期望。**
- 结构性原因（非 bug）：(i) 一次失败只影响 1 架无人机的 1–3 个包裹，穷举全部接机方案后单次节省上限约 12–35 元，而一个班次总成本 200–730 元；(ii) 每环境平均只有约 0.7–1.2 次失败，且仅 10–17% 的恢复会选跨车，只有约 8–13% 的环境出现过跨车恢复；(iii) 包裹保管链使地面任务无法在车间重分配，X 的额外自由度只有"选哪辆车接机"。
- 因此"差几百元"或"≥5% 总体"在这个模型里不可能靠修 bug、调算法或 X 专用算子得到；强行达到只能靠大幅抬高失败率（如每班 ≥10 次失败），那已脱离规范与现实依据。
- 已验证无效的路径（都做了、如实报告）：RETARGET 算子、三个 X 专用跨车算子、算法参数网格、CRN、预算×3。

**补充（light2 标准配置，2026-11-13 更新）**：light2 主实验总体 Δ=0.45 元（0.09%）；事件级（light2，条件）：基线 8 个跨车事件平均省 2.87 元（0.90%），池=空送 M=3（50 客户）5 个跨车事件平均省 4.84 元（2.12%），最大单事件 11.98 元（5.22%，C50，同一个事件在两组里各出现一次，合并时有重复）。
结论不变：light2 下总体平均不可能 ≥5%；跨车被采用的环境占 13%–20%。light2 的敏感性场景（池/失败数/H 余量）因 CPU 紧张按指示停止，**未完成**（H900 只跑了约 40%），本报告第 6.3 节只含基线。


## 9. 论文建议配置与叙事
**建议的最诚实且最有说服力的配置与叙事**
1. **主配置**：原规范（重型机、1 架/车、车载充电）作为主实验，因为它是规范设定；同时给出轻型 1 机/车换电作为"现实微卡"配置。两者 X 都有（边缘）显著优势：spec 0.59 元、light1 0.98 元（后者 95%CI 不含 0）。主表同时报告 STOPPED、X 更好/相同/更差。
2. **主结论的表述**：不要写"X 平均显著更省"。建议写：**(a) X 的可行域包含 S，故 X 不会更差（除搜索噪声）；(b) 跨车接机的价值是"条件性/事件性"的：仅在约 10% 的环境、约 10–17% 的失败恢复里被采用，被采用时平均省 ≈6 元（≈1.5% 的班次成本），最高 ≈5%**；(c) 价值随失败压力上升（池=空送、M=5 时总体 1.15%，C50 3.6%）和资源紧张度（每车 1 架 > 2 架）而增大。
3. **三条可作为论文贡献的实证发现**：失败越集中、无人机资源越紧，跨车越有价值（敏感性表）；跨车价值来自"接机车选择"而非额外的搜索算子（算子消融无增益）；事件特征：剩余时间越多、失败机电量越高，跨车节省越大（ρ≈0.5/0.4，样本小，作讨论）。
4. **必须写清的口径**：跨车占比分母 = 失败触发的恢复；Δ 仅在 S、X 都完成的对上统计，STOPPED 全部单列；事件级分析标"条件统计"；强制失败/池=空送均为敏感性分析，不替代主实验。
5. **如果还想要更醒目的数字**，只能走正当途径：(a) 用时间类指标（失败包裹延误、完工时间）——目前 X 并无优势（成本优先）；(b) 把规模放大并报告绝对元数（200 客户单班 Δ 更大，但比例不变）；(c) 年化/站点网络推算，明确标"推算"；(d) 把"资源紧张"场景（1 机/车、少车、H 紧）作为主打应用场景，而不是全体平均。
