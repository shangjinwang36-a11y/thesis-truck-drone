# 模型与算法实现说明

本文说明 `src/tdr` 如何把 V6.1 规范中的业务规则、数学模型与唯一算法落到代码。
符号与公式以规范为准，这里给出**实现视角**的关键定义与数据流。

---

## 1. 数据与实例

- `data.py`：从规范 TXT 中按标记提取附录A JSON（规范化 SHA256 = 99536ff4…）与附录B 源码
  （字节 SHA256 = 847814f8…），写出 `data/package.json`、`data/cases/*.json`、`data/reference/`。
- 客户 ID `c001…c100`，包裹 `p001…p100`（一客一件）；仓库坐标 `(10000,10000)`。
- 距离：二维欧氏；卡车 25/3 m/s，无人机 15 m/s。

## 2. 计划表示（`plan.py`）

```
Plan
├── routes[truck] : [visit_id...]          车辆有序访问链
├── visits[vid]   : Visit(truck, customer, ground=[])   一次访问，独立 vid
└── sorties[sid]  : Sortie(drone, truck, launch_vid, mode, lam,
                           air=[parcel...], rec_vid, handover=[...])
```

- `mode=ARC`：在 `launch_vid` 之后的道路弧上以 λ 连续放飞；`mode=STOP`：在访问驻车期放飞；
  `mode=AIR`：恢复阶段的空中残段（`started=True`，`start_time/start_pos` 确定）。
- `handover`：异常回收时在回收点交接、随后由接收车地送的票（含失败票）。
- 约束：每票恰好一次 G 或一次成功空送；每航次载荷 ≤30 kg；无人机链“上一回收后承运车 =
  下一航次放飞车”；所有航次在客户点回收。

## 3. 能量与充电（`schedule.py`、`config.PhysicalConfig`）

| 环节 | 公式 |
|---|---|
| 巡航 | `E_fly(l,m)=β·E_cap·l/(28000−400m)` |
| 悬停/服务/等待/L/R | `P_h(m)=β[P0+(P30−P0)m/30]`，`E=P_h·t/3600` |
| 电池 | `E_cap=3.9688`，回收余电 `E_min=0.1E_cap=0.39688` |
| 充电 | 阶段内线性：`ΔE=η_slot·q_b`，`q_b≤2 kW·dt`，整车 `Σq≤4 kW·dt`，`Σq≤A_k` |

- 充电阶段 = “同一机、同一实际承运车、连续具备充电资格”的最大时间段；
  P/L/R/U、离车、空中都不充电；READY 可充到 L 开始；返库路段按同一规则。
- **充电 LP**（每次完整评价调用一次）：变量为各充电阶段的交流输出 `q_b`，
  目标 `min Σq_b`（等价于最小化电费，因为 `c_vehicle−η_slot·c_depot>0`），
  约束为逐阶段端点电量、R 结束余电下限、电池上限、单槽/整车功率、每车交流预算。
  内部调用 `scipy.optimize.linprog(method="highs")`。
- 成本：`C=c_km·D/1000 + w_s·ΣF_k + c_vehicle·Q_ac + c_depot·Σ(E_cap−E_return)`；
  `z=max_d t_return(d)`，字典序比较（1e-4 元、1e-3 s 容差）。

## 4. 调度（固定点前向传播）

给定结构与 λ，求各访问到离时刻、无人机各阶段起止：

1. 卡车顺序扫描访问：到达 `t_arr=t_dep_prev+D/v_T`；
   访问内串行执行 R(+U) → G → P；出发时刻 `t_dep` 满足 P 完成、通道空闲、无人机可用。
2. 无人机由 L 结束位置起算：巡航 → 60 s 服务（按释放前载荷扣电）→ … → 回收点；
   若先到则在回收点悬停等待（按载荷扣电）。
3. 卡车在回收访问等待无人机真实到达；重复 1—2 直到时刻不再变化（≤14 轮）。
4. 记录 `launch_times / rec_times / drone_arrival / drone_ready_before`，供 LP 与截断使用。

**与规范的差异**：规范要求“参考构序 LP + 成本 LP + z LP”三阶段求解固定结构；
本实现用确定性前向传播取“最早可行”，再由充电 LP 决定补能，成本仍按真实公式核算。
该差异已在 README 与结果分析中声明。

## 5. 名义计划（`nominal.py`）

1. 五车全地送初解：按 `atan2` → 距库距离 → 客户ID 排序，连续分 5 段（前 N mod 5 段多 1 个），
   段内最近邻，返库；直接前向计算 `C_ground`。
2. 空送转换启动：按“删除连续 1—3 客可节省车程”降序，尝试前 40 个结构，
   对每个结构完整评价；接受改进；重复直到无改进或预算用尽。
3. 固定 ALNS（见下）。
4. 结束前对最好解做一次坐标细化；`H=max_k F_k+1800 s` 由核验后的名义计划固定。

## 6. ALNS（`alns.py`、`moves.py`、`operators` 内嵌）

- 移除：D1 随机、D2 受影响航次、D3 回收资源、D4 能量链、D5 支援访问、D6 航次重组；
  对航次整体释放（依赖闭包），再补足 q。
- 修复：R1 代理增量贪心、R2 regret-2；代理分数
  `Ĉ=c_km·L_T/1000+w_s·(L_T/v_T+50n_G+30n_P+30n_R+20n_U)+c_depot·E_air_no_wait`。
- 接受：SA，`T0=−0.01·max(C_init−C_prefix,1)/ln0.5`，`T(p)=T0·0.01^p`；
  成本容差内比较 z；不可行候选永不进入工作解。
- 权重：每 25 轮 `w←max(0.1,0.8w+0.2·s/n)`；奖励 33/9/3/0。
- 连续位置：5 个基础向量（继承 λ、全 0、全 1、0.25、0.75，必要时 0.5 补足），
  逐维 ±h 模式搜索（h 0.25→0.001，最多 40 次额外评价）。
- 局部重排：同一访问的回收/放飞顺序、相邻访问交换，最多 6 个事件，枚举后完整回验。

## 7. 恢复与截断（`simulate.py`、`recovery.py`）

事件驱动执行：

```
调度 → 按时间扫描空送到达 → 查询隐藏环境
   ├─ 可空送：记录观察，继续
   └─ 失效：t_cut = 所有进行中固定动作的结束时刻（失败机自身服务除外）
        → truncate：保留在飞残段、卡车残段路线、前缀里程/交流电/已交付
        → initial_recovery：骨架 + 重建，枚举（回收车, 回收访问, 继续空送子集）
             · S：仅原放飞车；X：全部在班车（原放飞车候选优先）
             · 同点支援访问 / 异点访问 / 跨车
             · R→U→G 闭包，失败票强制地送
        → ALNS 热启动优化 → 独立核验 → 执行新后缀
```

- 失败机在失败客户处悬停到 `t_cut`，悬停能量按机上实际载荷扣减；失败票不释放、不减载。
- 已观察失败累积到 `ground_required`，修复器禁止再把它们排成空送。
- 若预算内得不到完整可行后缀，返回 `STOPPED_NO_FEASIBLE_SUFFIX`，保留真实前缀，不直飞仓库。

## 8. 独立核验（`verify.py`）

从计划与快照重新调度并重算：结构/交付唯一性、载荷、S 策略资格、能量链、回收余电、
机位 ≤2、通道 ≤1、H、终端随车返库、成本分项；输出 `verification.json`。
核验器不读取优化器的 `feasible` 布尔值，也不直接采信账面总成本。

## 9. 实验与输出（`experiment.py`、`report.py`）

- 名义计划每图一次，十种子与 S/X 复用；`run_episode_dir` 写全部机器可读文件与三张图。
- 批量输出 `episodes.csv`、`paired_results.csv`、`summary.json`、`status_counts.csv`、`paired_delta.png`；
  配对统计严格保留不可行/未求得与负差值，`n_pairs=0/1` 时均值/标准差/区间按规范置空。
