0  已确定规则与交付范围

本版统一采用以下规则；后文、配置和实现均应遵守：
1. 车可在任一客户点停车接机，包括失效客户、已服务客户、其他车辆负责的客户及原路线之外的客户；允许专程插入访问或重访。
2. 失效仅指客户空中交付作业不可用；无人机本体仍能正常飞行，地面送达与车载回收能力保持有效。车辆停靠后提供可用接机平台，是本模型的统一运营假设。
3. 除客户点和仓库起终点外，车辆不设运营停车点；无人机放飞位置不受客户节点限制，可沿车辆实际运行轨迹连续选择。
4. 每个环境种子随机设置1—2个不同的隐藏失效客户订单；到点后才知道，原始公开计划不能读取这些信息。
5. 允许任意航次、任意票失败；保留立即带货回收、继续其他票后回收、完成部分后回收三种选择。
6. 取消等待投递条件恢复、改投重试和F固定场站；不设置新增空送一票、一次航次或全班仅换车一次的限制。为车机接驳产生的真实等待仍允许，并按实际载荷扣除悬停电量。
7. 每张基础图使用预先固定的10个环境种子成对比较S/X，报告均值、波动、实际触发次数与可行性状态。
8. 失效客户原地等车、回收后当场地送是合法候选；不强迫无人机先离开、不强迫异点接机，也不保证跨车或异点接机必然有收益。
9. 同点回收仍依次执行R回收、U卸货交接和G地送。车辆到达、无人机回收或货物卸下，均不等于客户订单已经妥投。
10. 所有客户都具有接机候选资格，不表示车辆可以不在场接机。模型联合选择接机位置、车辆、访问和时刻，并核验能量、机位、通道与司机作业。
11. 无人机已固定在实际承运车的机槽内且设备就绪时，车辆行驶和合法停车期间均可充电，包括完成准备但尚未开始L的在车阶段，以及最终随车返库路段。充电不占司机操作时间，仍按功率、实际电量和电池容量计量。
12. 所有出飞航次，包括正常航次、异常航次和最后一航，均须在某个客户点由卡车回收。无人机最终由实际承运车载回仓库，不允许独立飞回仓库、在仓库独立降落或先到仓库等车。

“客户点外不停车”和“客户点外允许放飞”同时成立时，本版按字面采用行驶中自动放飞。这是新增的设备/操作模型假设，不是对现有商用平台实际能力的证明。人工装载准备仍在客户停靠点或出库仓库完成，司机不一边驾驶一边装载。若实际项目不允许行驶放飞，需要另设途中放飞短停例外；两种版本不能混用。

1  资源、业务和位置集合

1.1  机队与订单

5辆卡车、5架同型且有唯一编号的无人机；每车出库1架机，每车最多承运2架。普通包裹一客一件、不拆分，卡车包裹容量不约束。所有客户地面可达。单航总载荷不超过30 kg；正常与恢复后的空送均可一航多票、多航次连续执行。

无人机的身份、电池、当前承运车和包裹保管者连续记录。无人机换车不让其他货物跟随瞬移。已交付订单不回滚，已完成作业不撤销。

本文只研究客户空中交付条件失效，不研究无人机机体损坏、整片空域不能飞行、车辆无法到达客户或地面收件也不可行的事件。发现失效后，无人机仍可携带货物飞行、继续其他允许空送的订单或前往接机点。失效票只改变交付方式，不代表该票已经交付。

正常空送按统一悬停交付作业处理，每票成功服务60 s后才释放货物。机队、车载平台和包裹释放机构采用合成研究设定。公开机型参数只作为能量尺度参照，不表示0.2—5 kg包裹装置和移动放飞平台已完成实物验证。

1.2  客户点停车接机

设V为全部客户地点，途中运营停靠集合为：
  V_stop = V。
仓库只作为班次出发和结束边界保留，不是F中转站。

接机候选集合：
  V_recovery = V。
该集合对所有正常、异常和末航次一致适用，仓库不属于接机候选或无人机独立终端降落地点。仓库允许班次起点的人工准备和放飞；班次末无人机只随车到库。

即使客户已服务、由另一辆车负责、没有该车的待配送货物，也允许该车前往该客户点停车接机。这类访问是支援停靠，不增加客户需求，不重复计为交付。允许重复访问同一客户点，每次访问均有独立visit_id。

接机候选不受“原剩余访问”“新增地送访问”或另外筛选的支援目录限制。失效客户同样属于V_recovery。模型不因某客户被私有环境抽中而预先改变公开停车或接机资格。

空送失效指订单不能通过客户的空中交付位置或设施完成，卡车停车后依然可以利用车载平台接回无人机和货物，地面收件保持可行。宏观路径模型将客户交付位置及其邻近车辆服务位置聚合为一个节点；同一节点在模型中的功能可以不同。不能同时把该事件写成“整个区域不能飞行或接近”，又允许该处无条件车载回收。

本版接机候选只含全部客户地点，途中不加入非客户道路节点。文献中的额外道路会合节点仅作为以后扩展的参考，不进入本版算例。仓库是班次起讫位置，不承担F固定场站中转、途中存货取货或额外补给功能。

接机必须真实停车。对接机车k在客户j的一次独立访问v，记车辆到达/离开时刻为a_T(k,j,v)、b_T(k,j,v)，无人机d实际到达该次接机位置的时刻为a_D(d,j,v)，则：
  s_R(d,k,j,v) ≥ a_T(k,j,v)；
  s_R(d,k,j,v) ≥ a_D(d,j,v)；
  s_R(d,k,j,v)+tau_R ≤ b_T(k,j,v)。
带货异常回收还要在离开前完成必要交接U。司机/通道未空闲时，R不能仅按max(a_T,a_D)立即开始。机位、回收通道和司机作业仍必须可行。

每次访问均使用独立visit_id。同一客户被支援重访时，不能沿用该客户上一次访问的到离时刻或已结束的机位状态。“车停即可接机”表示位置资格成立，不免除实体资源和实际到场条件。

为了接机新增的车辆绕行、停车、等待和交接时间全部计入实际路线、工时和费用；没有任意路边停车点。

1.3  放飞位置

放飞可发生在车辆实际轨迹上的任意位置，包括客户点停车期间和客户点之间的行驶路段。模型同时选择放飞车辆、所在实际道路弧和连续位置。位置必须与该机仍在车上的真实运动轨迹一致。

这里的“任意位置”是在所选实际车辆路径上的连续位置，不允许飞机从车辆从未到达的坐标出发。接机点插入会改变车辆路线，也会改变可放飞的轨迹。不能把放飞候选悄悄退化为原客户节点。

当前地面与空中距离沿用二维欧氏几何。车辆在相邻访问间匀速直线运动；如换成真实路网，放飞位置应沿所选道路折线的连续里程定义，而不是跨越道路外的直线位置。

1.4  客户点回收与随车返库

对每一个实际执行或计划执行的无人机航次s，均要求：
  recovery_customer(s) ∈ V。
完成最后一票、机上已经空载或电量足够飞回仓库，都不构成独立返库的例外。候选结构不生成无人机直飞仓库的返库航段，不生成仓库接机R，也不设置“无人机已在仓库等车”的终态。

设无人机d全班最后一次实际回收由车k在客户j的一次访问v完成，则：
  s_R(d,k,j,v)+tau_R ≤ b_T(k,j,v) ≤ T_depot(k)。
若需要异常货物交接U，则还须：
  s_U(d,k,j,v)+tau_U ≤ b_T(k,j,v)。
T_depot(k)为该车本班最终到库时刻。从最后一次回收结束到车辆入库，无人机始终在实际承运车上并占用机位，可以随车继续访问其他客户，并在满足资格时充电。若后来又执行L，此前的回收就不是最后一次回收，后续航次仍须再次在客户点接回。

最终承运车以真实机体流为准，并继续遵守S/X回收规则；不要求每架机由出库时的原始所属车载回。X允许的一次跨车回收后，可由接收车最终载回。各车最终机数可以不同，一车空机返库、另一车载两架返库可以成立，但每车始终不超过2机位，机体不能凭空换车。

始终未起飞但随车出库的无人机直接随该车返库，不虚构客户点R。整班未出库的机体留在仓库，入库时刻记为0；不为它虚构运输、充电或回收作业。对随车出库的机体：
  t_return(d) = T_depot(final_carrier(d))；
  return_mode(d) = ON_TRUCK。
客户点R结束、最后一票妥投以及随车实际入库是不同事件。接机不必安排在车辆最后一个地送客户；允许更早接回后继续随车工作。

若找不到满足电量、时序、机位和班次时限的客户点回收方案，按求解证据报告INFEASIBLE或NO_SOLUTION_LIMIT，不能临时加入直飞仓库作为隐藏兜底。

2  人工准备与自动放飞

2.1  P与L分开

P为30 s人工准备，在客户停车访问或首次出库仓库完成，与G、R、U等司机人工动作串行。P完成时，将本航次真实装载的包裹从车辆库存移至无人机。

准备完成后，无人机进入READY_ON_TRUCK状态，仍占机位，可以随车移动，尚未独立飞行。删除原“P/L必须紧接”的要求，改为：
  s_L ≥ s_P + tau_P。

L为10 s自动动力放飞，允许与车辆DRIVE重叠，不占司机操作时间。L按实际起飞载荷扣除动力能耗。L结束时无人机真正离车，机位释放，独立飞行段才开始。

同一车载起降作业通道不同时执行两个L或L与R；这是沿用单通道车载作业布局并明确其自动放飞占用。人工准备P仍受司机串行约束。不得通过开放移动放飞默认增加第二名司机或额外操作员。

P/L/R/U期间本机不充电。准备完成后、L尚未开始的机体仍固定在车，可在车辆行驶或合法停车期间充电，直至本机L开始；不要求车速为0。充电自动进行，不占司机操作时间。已准备货物如需改回地送，必须在合法停车点进行真实卸货交接并计U，不能在重规划时直接改写保管者。

2.2  连续位置与时间

车辆在道路弧i→j上，端点坐标为x_i、x_j，距离D_ij，离开i的时间v_i，车速v_T。定义lambda∈[0,1]，放飞点统一指L完成、机体真正离车的位置：

  x_L = (1-lambda)x_i + lambda x_j；
  t_L = v_i + lambda D_ij / v_T；
  s_L = t_L - tau_L；
  s_P + tau_P ≤ t_L - tau_L。

若车辆已驶至该弧lambda_0，新的放飞决策不能选择已经经过的部分，且不能回溯到当前时刻以前。L跨越弧边界或部分处于客户停车期时，使用一般定义：
  x_L = x_truck(t_L)。

当前位置、L开始位置和L结束位置不能混淆。当前v_T=25/3 m/s、tau_L=10 s；全程行驶的L期间车前进83.33 m。不能使用L开始位置计算无人机离车后的首段距离，同时又让车辆继续移动10 s。

2.3  放飞后的飞行与成本

首个空送客户a的飞行距离与到达时刻：
  l_La = ||x_L - x_a||_2；
  t_a = t_L + l_La/v_D。

L结束电量为L开始电量减去P_h(m)tau_L/3600。无人机随车移动的道路距离不计为独立空中巡航；L结束后才按真实空中航段扣电。

选择不同lambda会改变飞行距离、服务时刻、回收同步、等待、后续任务及入库时间，进而改变总能耗和工时。若为放飞调整实际车辆路线，额外里程和时间照常计费。无需另造一个“放飞位置惩罚系数”。

接机与放飞地点的规则不同：接机必须在客户点停车，自动放飞可在实际行驶轨迹上发生。

3  隐藏失效环境与动态信息揭示

3.1  抽样总体与数量

默认候选集合为本图全部具有空送资格的客户订单C_air，包括名义计划中原本由卡车配送、但物理上允许空送的订单。当前六图全部客户均属于该集合。这样落实“任意客户点”，不只在名义空送序列里筛选。

候选数至少2时：
  M ~ Uniform({1,2})；
  F_seed = 从C_air无放回抽取M个客户。

M=1和M=2各半是基准情景设定，不是实际故障统计。只有1个候选时M=1；无候选时M=0并记录NO_EVENT。十个种子里1票/2票不要求恰好各5次，不为平衡或收益而重抽。

同一seed内选出的客户不同；不同seed自然重复选到同一组点可以保留。环境种子由case_id和environment_seed共同标识，派生方式固定并登记。名义计划种子、环境种子和求解算法种子分开。

失败集合以customer_id/parcel_id为稳定标识，不绑定原航次ID、访问序号或名义到达时间。第一故障发生后路线改变，不会让第二个失效对象跟着重新抽样。

这是一客一件下的隐藏订单可用性模型。它在实际空送到达时揭示，不模拟故障开始/修复的时空持续过程，也不引入等待修复。所谓“实时”是指信息在执行中的实际到达事件发生时才进入公开状态，而不是要求程序调用现实时间sleep。若以后研究真实时间区间失效，应另建环境版本。

从六图数据导入时，整数客户号统一映射为c001、c002……，一客一件的包裹号对应p001、p002……；在本版最大100客户的范围内统一三位补零。候选列表按(customer_id,parcel_id)排序后抽样，不能改变ID编码或排序又声称同一seed必然复现。

环境伪随机种子由UTF-8紧凑JSON列表[generator_version,case_id,environment_seed]的SHA256摘要按无符号大端整数解释得到。发生器版本保持customer-failure-v3-1，随机步骤依次为choice([1,2])与对已排序候选的sample；候选不足2时不执行数量抽样。记录Python版本，回合结束后保存完整环境审计名单。只升级文档版本不改变发生器字符串，不重新抽取已有环境。

3.2  设置的失效点不等于实际观察次数

每个seed设置1—2个不能空送的客户，但某个客户可能一直由车送，或第一故障后改为地送。该客户不产生空送到达，就不会触发空送失败观察。

因此实际观察次数可以为0、1或2。不能为了让每个策略都恰好观察两次失败，另外抽取新客户，也不能因没有实际失败就丢弃seed。这是策略在同一环境下产生的合法差异。

如果未来专门研究“至少遭遇一次空送失败后的条件恢复”，可以另做从名义拟空送客户抽样的实验，但必须另标抽样总体，不覆盖或替换本版全客户口径。

3.3  信息隔离

环境私有：实现seed、未揭示的失败集合、环境随机状态、运行结束后的审计记录。
公开计划：正常客户资格、任务、路线、时间和机队参数。
规划器：只接收已观察信息、真实当前实体状态、已完成任务、不可撤销残段和剩余需求。

禁止给规划器传入environment对象、当前环境seed、实现后的M、未来失败客户列表或可逆编码这些信息的标识。公开计划不能预先把失败客户的air_eligible置为false。

每次DRONE_ARRIVAL发生时，由仿真器查询环境，生成公开观察：
  observed_at_s、customer_id、parcel_id、drone_id、flight_id、
  air_delivery_available、
  ground_delivery_available=true、
  truck_recovery_available=true。

仅在实际到点发现不能空送时，把该票加入ground_required_parcels。包裹保持在机上，不释放、不记妥投。正常交付则在完整60 s服务结束后才释放并减重。失败发生在交付服务开始前，不扣一段不存在的成功服务时间。

两个世界若截至当前时刻的公开历史一致，规划器在相同自身算法随机状态下应作同样决策。环境私下预抽样只是可复现机制，不表示调度器提前知道。

3.4  多次揭示与时钟

每次失效到达即观察并触发重排：
  t_replan = t_observed = t_arrival。
不设置原20 s确认、120 s等待投递条件恢复或替代点重试流程。该条不取消接机同步等待；接机等待计时、计能耗，见4.5节。

已观察失败的历史订单、客户以及受影响航次/机体集合累积维护。第二次失败不能覆盖第一次失败票，所有历史保管者、电量和已发生费用继续接续。

ground_required是订单强制地送属性，可以在妥投后保留作为历史记录；当前待安排失败票等于ground_required订单与undelivered订单的交集。已地送完成的历史失败票不能因仍带有该属性而被重复派送。

同刻多个到达应先结算已完成动作，再汇集该时刻实际发生的观察，更新状态后统一触发一次恢复。不允许为了求解顺序任意遗漏同刻已知道的故障。

这里是虚拟时钟中的动态信息揭示，不依赖sleep。即时决策基准decision_latency_s=0；计算墙钟耗时单列。实际在线延迟验证必须推进车辆和无人机并扣除等待电量，不能冻结现场等待求解。

4  任意票失败后的配送、回收及同点等待

4.1  机上完整剩余货物

无人机d在时刻t的未交付集合为B_d(t)，其中已观察失败且仍在机上的集合为B_d(t)∩G_req(t)。G_req(t)是已确认必须地送的全部订单。

允许模型选择：
A. 立即带全部剩余货物回车；
B. 携带失败票继续完成其他可空送票，再回车；
C. 完成其中一部分后回车，再安排剩余订单。

第二个客户可能仍是隐藏失效点。继续空送时只能使用已知资格，抵达后再获知真实结果，不得利用隐藏名单提前避开特定失效客户。允许仅凭公开成本、路线和资源信息改地送或调整访问顺序；未进行空送尝试的订单按真实业务执行。

每个飞行航段的载荷为机上全部实际未卸货物之和，包括全部已经失败但还未交接的票。不能固定成单个p的质量，也不能在失败时错误减重。

4.2  S/X策略

对每个受到已观察交付失败影响的在途航次：
S：只能回收到本航次实际放飞车；
X：可回收到任一合格且仍在班次的车辆，包含本航次放飞车。

“原车”取该航次launch_truck_id。同一航次先后两票失败，原车不改变；若机体先从A转到B，再从B启动新的航次，则新航次原车为B，不能始终套出库绑定关系。

两侧均允许在全部客户点接机，并允许插入/重访；均允许连续放飞、多票多航次以及三类机上余货处理。普通未受失败影响的航次按当前约定承运关系执行；已有在途承诺不能被事后抹除。若其后也观察到失败，再按同一规则解除和修复。

异常回收后普通新航次从当前实际承运车取货并返回该车，不设普通航次数量上限。若之后再次失败，X可再次依当时状态选择接收车；不因全班已经换过一次车就拒绝。不开启无实物作业的任意卡车包裹转移。

4.3  交接与重排

R结束机体到车，U完成后，机上仍未交付的实际货物转给接收车：
  s_U ≥ s_R+tau_R；
  s_G(i) ≥ s_U+tau_U。

本版U=20 s代表一次异常回收后的批量交接，不按包裹件数重复收取。已失败票继续地送；未失败票仍可地送或重新空送。

已完成动作冻结，正在执行的不可撤销道路段与地勤接续。当前道路段可进行已准备机体的自动放飞，但不能回溯位置或临时在非客户点停车。

受影响机尚未开始的后续航次必须可重排。全队尚未开始任务可重新选配送方式，但货物必须从真实持有车/机取得。原普通地面任务中仍保留地送的任务，其相对服务次序作为当前局部恢复框架保留；已经改为空送的任务可从该地送序列删除，新增地送及纯支援访问可插入。纯支援重访不构成再次执行该客户的原地送任务。这一范围限制须如实说明，不把结果称为全队任意重排的全局VRP最优解，也不把接机点限制为原路线节点。

其他未受已观察交付失败影响的在途航次，保留其已承诺的剩余访问顺序与回收承诺，允许同步时刻接续调整，新增等待必须计能；若其后自己也发现失败，再按同一规则恢复。尚未出动的后续航次可重排。已结束班次或从未出库的车辆不为救援额外启用，机队资源不增加。

4.4  不设置新增空送数量上限

设U(t)为未交付需求：
  Σ_k g_ik + Σ_(d,r) y_idr = 1，i∈U(t)。
r包括当前在途航次的剩余部分及后续新建/重排航次。
  Σ_(d,r) y_idr = 0，i∈G_req(t)∩U(t)。

每票一次、真实货物流、30 kg载荷、电量、同步、机位和H共同决定可安排多少票及航次。没有max_extra_sorties=1、最多一个q或每航次额外客户数上限。不强制使用无人机，也不设置空送比例。每个计划配送航次应至少装载并拟服务一票当时允许空送的未完成订单；执行中因随机失效导致实际成功交付为零的中断航次合法，不为凑成功票强制继续配送。该航次保留真实轨迹，异常带货回收单独记为恢复动作，不伪装成新的配送航次。

4.5  同点等车、接机和地面交付

无人机在失败客户处悬停，等待原车或其他合格车辆到场，完成回收后由接收车在该客户处地送，是合法恢复候选。失效发生前，规划器不知道该客户不能空送；先前已经发生的飞行和费用不能事后撤销。不能用事后知道故障的视角否定正常出发决策。

同点恢复的实体顺序为：
  AIRBORNE_WAIT → R回收30 s → U批量卸货交接20 s → G地送50 s。

R开始前包裹在空中无人机上；R完成后机体已到车，包裹在U完成前仍记在该无人机保管清单；U完成后才转给接收车；G完成后才记为客户妥投。车到、机落、卸货均不能直接替代G完成事件。R/U/G由同一司机顺序执行，无其他冲突时至少需要100 s；有资源冲突或其他任务时可能更久。

机上所有未交付包裹都计入等待与回收载荷，不只计算当前失败票。等待期间不充电、不减载，不将无人机默认切换为独立落地关机状态。本文没有独立地面落机保管、离车充电或免费地面等待动作。

设发现失败时余电为E_f、机上实际载荷为m。若此后只在原地等w秒再执行R，且载荷不变，则：
  E_f-P_h(m)(w+tau_R)/3600 ≥ E_min；
  w ≤ 3600(E_f-E_min)/P_h(m)-tau_R。

上式是这一特定“原地等待后直接回收”候选的必要能量条件，还须同时满足车辆到达、司机、通道、机位和H。右侧为负时，表示连立即回收也不能满足余电约束；不能截成0后判为可行。若先飞往其他节点、继续交付或增加其他动作，应对真实分段轨迹逐段扣电，不能套用这个简化式。

不设新的固定等待上限。有限电量、真实到场时间、后续任务和班次时限共同约束等待。算法不能把同点等车写成唯一默认动作，也不能为了得到异点或跨车方案而将其删除。

4.6  同点与异点接机的构造说明例

以下是采用本文参数计算的说明例，不是正式求解结果。故障发现为t=0，三处位置共线：卡车在0 m，正常地送客户q在1500 m，失败客户p在3000 m；无人机已经在p，携带1 kg失败包裹。卡车30 km/h，无人机54 km/h。q需G=50 s，两种方案均不充电。

方案A：无人机在p等车。卡车180 s到q，服务至230 s，再行驶180 s于410 s到p；410—440 s回收，440—460 s卸货，460—510 s完成p地送。无人机悬停与回收总计440 s。

方案B：无人机飞回q。飞行100 s后等车80 s；车在180 s到q，180—210 s回收，210—230 s卸货，230—280 s完成q地送，再行驶180 s于460 s到p，460—510 s完成p地送。

两方案本段车程均为3000 m，p均在510 s妥投。按实际载荷模型：
  P_h(1 kg)=8.3785777778 kW；
  A耗电=8.3785777778×440/3600=1.0240483951 kWh；
  B飞行耗电=3.9688×1500/27600=0.2156956522 kWh；
  B等待与回收耗电=8.3785777778×110/3600=0.2560120988 kWh；
  B总耗电=0.4717077509 kWh，少耗0.5523406441 kWh。

若发现失败时E_f=1.20 kWh，A回收后余电约0.17595 kWh，违反0.39688 kWh的回收余电约束；B约剩0.72829 kWh，满足该能量要求。q的服务完成时刻在两方案中不同，本模型未设逐客户时间窗；不能把这一说明例扩读成对任意服务时限都等价。

因此，车辆最终必须到p地送，并不意味着无人机必然应留在p等候。反过来，当车辆很近、余电充足且异点接机增加绕行时，同点等待也可能合理最优。结果由真实可行性与成本决定。

5  S/X共同环境、十种子实验与恢复分类统计

5.1  第一次失效前共同，之后各自推进

每图先生成并核验同一份不读取未来故障信息的名义计划，再固定该计划，对environment_seed=1,…,10生成不同隐藏环境。

同一case、plan、seed下，S/X共享相同失败客户集合、物理参数、成本口径、H和每次重排预算。第一次实际失败前可共用真实前缀；第一次失败后各自执行自己的动作，继承各自实际位置、载荷、电量、库存和费用。

第二次失效不要求在两侧同一时间发生，也不要求两侧都发生。某策略先改地送就可能不再观察该失效。不能在第二次故障时把S/X重置成同一个快照，更不能按各自随机调用次数重新配给故障。

若全部失效客户都由地面完成、没有空中失败观察，保留该seed，标记NO_OBSERVED_AIR_FAILURE，不补抽。

5.2  不保证每个种子的最终成本X都更低

在相同已知状态、相同确定性子问题下，X包含S的允许恢复结构，精确子问题最优成本可检查C_X*≤C_S*。

但多次未知故障下，两侧从第一次重排后进入不同状态。X当前选择可能在尚未知晓的第二次失效后导致最终成本更高，即使当时子问题被精确求解，也不一定是程序错误。

因此每个seed的最终实际成本差可以为正、零或负，必须全部保留。不能把负收益统一说成求解不精确，也不能凭可行域包含就宣称每条动态样本路径都单调改善。若讨论全程策略类的最优期望成本，需要另有相应随机优化定义和证明。

5.3  统计口径

同一seed成对差值：
  Delta_s = C_S,s - C_X,s。
正值表示该实现下X成本较低。

若10对均有完整核证方案：
  mean_Delta = (1/10)Σ_s Delta_s。
同时报告差值标准差、最小/最大值、正差/零差/负差个数和逐seed结果。

可在差值独立抽样及相应分布近似成立时给出：
  mean_Delta ± t_(n-1,0.975) s_Delta/sqrt(n)。
不能把“10个seed取均值”当作自动可靠性保证；差值波动很大、明显偏斜或区间跨零时，应据实表述结果不稳定/证据不足，再决定是否增加重复次数。

若仅n_pair对两侧都有完整核证解，成本均值只能用这些真实有限配对，并明确为“两侧均可行条件下的成本比较”。完整10个seed的求解/可行性状态必须同时报告，不能删掉困难事件后声称总体均值。n_pair=0时成本差均值为null；n_pair=1时可报该差值，但样本标准差和均值置信区间为null。不得以0代替缺失统计量，也不得继续用10作为有限配对均值的分母。

区分：
- 一侧核证有解、另一侧已证不可行：可行性改善；
- 一侧有解、另一侧仅时限未找到：本预算内找到方案的差异；
- 两侧均无完整方案：保留，不用零或人为巨额成本填入均值；
- 没有实际空中失效：按全客户抽样口径保留。

结果至少含：
case_id、nominal_plan_id、environment_seed（只在实验审计/结果中）、
设置失效点数M、运行结束后的失效客户审计列表、
S/X各自观察到的失败票数、未触发空故障而直接地送的失效票数、
S/X状态、成本、工时、车程、耗电、最后入库时间、

5.4  同点/异点和原车/跨车的两层统计

回收动作层以recovery_id为唯一主键，按实际实体动作计数。记录flight_id、drone_id、launch_truck_id、recovery_truck_id、recovery_customer_id、recovery_visit_id、R起止时刻、回收前机上已观察失败票及真实分段能源记录。

原车回收：recovery_truck_id=该flight_id的launch_truck_id；否则为跨车回收。
动作层“在失效客户点回收”：接机客户属于本次回收前机上已观察失败订单的客户集合；否则为“在其他客户点回收”。这里表示与至少一票失败订单同点，不表示与全部失败票同点。正常回收与未携带已观察失败票的回收，另列，不进入异常回收比例的分母。

失败订单层以parcel_id记录该票第一次观察失败后承接它的首次实际回收first_post_failure_recovery_id。若其回收客户等于该票的failed_customer_id，则该票为同点回收，否则为异点回收。每票另记首次失败时刻、卸货完成时刻、地送完成时刻、响应时长和状态。

例：p1在客户1失败、p2在客户2失败，同一无人机最后在客户1由另一辆车接回。实体回收只发生1次；订单p1为同点跨车，p2为异点跨车。订单层四类数量合计为有相应记录的失败票数，不能称为接机动作数。未回收、未妥投的相关时刻与时长为null，保留状态，不以0替代。

总耗电、车程、工时沿实体时间轴累计一次。两个失败票共享悬停和回收时，不能分别记账后再次相加。每票响应时间可以独立记录。事件时刻相同的多个失败观察与最终回收动作数也不必相同。

至少报告：
  同点/异点×原车/跨车的失败订单分类；
  异常实体回收次数及在失效客户点/其他客户点的动作分类；
  空中等待时间与能耗、回收余电、失败票妥投时长；
  真实全班车程及其相对同一名义计划的差值；
  回收时仍未交付的失败票和其他票数。

全班车程差=实际全班车程-固定名义计划全班车程，可为负。该值包含所有改派效果，不直接等同纯救援绕行。若另报告某次重排的新增绕行，须单独定义比较计划；不同重排之间的局部差值不能随意相加冒充全班增量。

同点回收比例高可以是有效研究结论。不能筛掉这些环境、强迫异点回收、虚增等待罚项或改抽故障以制造跨车收益。

6.3  车载充电：行驶和合法停车期间均允许

充电资格取决于无人机是否已固定在实际承运车的机槽内、设备是否就绪，不取决于车辆是否停车。ON_TRUCK和READY_ON_TRUCK在满足这些条件时，均可与车辆DRIVE或合法停车重叠充电。正常回收须等R完成，异常回收须等U完成，再计既定充电就绪延迟；当前延迟为0 s。

本机P/L/R/U期间不充电；空中巡航、空中服务、悬停等车期间不充电。READY_ON_TRUCK可一直充至本机L开始。司机为其他订单执行G，或另一架机正在进行作业，不自动取消本机的充电资格；各机仍分别核验连接状态、机槽和整车供电上限。

车载充电为自动作业，不需要司机在行驶中操作。允许行驶充电不改变P/G/R/U必须停车且由司机串行执行的规则，也不增加途中非客户停车点。充电是有约束的可选决策，不要求每个合格时段都满功率充电，不要求为充满电专门停车。

将时间轴按充电资格、实际承运车、飞行/作业阶段变化等事件切分为区间h，长度dt_h秒。定义：
  Q_ac(d,k,h)：区间h内车k给无人机d输出的交流电量，单位kWh；
  chi(d,k,h)：d固定于车k机槽内且设备就绪时为1，否则为0；
  A(k,h)：区间开始时车k剩余可用交流电量；
  E_used(d,h)：区间内无人机真实消耗电量。
chi的定义不含“车辆必须停车”。约束为：
  0 ≤ Q_ac(d,k,h) ≤ chi(d,k,h) P_slot dt_h/3600；
  Σ_d Q_ac(d,k,h) ≤ P_truck dt_h/3600；
  A(k,h+1) = A(k,h) - Σ_d Q_ac(d,k,h) ≥ 0；
  E(d,h+1) = E(d,h) + eta_slot Σ_k Q_ac(d,k,h) - E_used(d,h)；
  0 ≤ E(d,h+1) ≤ E_cap。
各次回收另须满足6.2节的最低余电约束，各真实航段和作业的内部时刻也须核验能量可行，不能只核对整段净电量。充电达到容量时应停止或降低功率，实际输出电量才进入A与成本账本。

完整班次初始A(k,0)=4 kWh；重规划使用快照中该车真实剩余A，不能重置为4。跨车回收后，从实际接收车取电，扣该车的剩余供电量，不扣原放飞车，也不使用全队共享的虚拟能源池。同一时刻无人机只有一个真实承运车。

本版沿用每槽交流2 kW、整车交流4 kW、机槽效率0.90，单机满功率净充电为1.8 kW。满足资格、供电与容量均充足时，行驶10 min最多净充0.30 kWh，20 min为0.60 kWh，30 min为0.90 kWh。每车初始4 kWh交流预算最多转入无人机电池3.6 kWh净电量；行驶本身不刷新该预算。本版没有发动机途中发电或途中补充车载电源的额外过程。

R开始预留机位，结束转为在车；P和READY_ON_TRUCK仍占位，L结束才释放。从末次客户点回收到随车入库，也持续占机位。多故障可能使多架机考虑同一接收车，必须逐实体核验占位+预留≤2。

返库路段与其他道路段采用同一充电规则：已在车且就绪即可充电，计入相应车辆供电消耗、Q_net和到库余电。不能用未来回车后才会获得的充电量支持当前飞行、悬停或回收，也不能把一个跨越起飞/回收的粗区间净额作为中间欠电的补偿。

6.4  班次时限、完整成本与优化目标

名义计划须按本版停靠、连续放飞、行驶充电和客户点回收后随车返库的共同规则生成并核验，S/X执行前缀及恢复后缀均采用这一口径。旧版计划不得未经重新核验直接复用；涉及旧充电或终端规则的计划及成本须重新构建/计算，不沿用与之不匹配的旧H。实际不存在的名义计划不能假定已经生成。对最终采用的同一新版名义计划固定：
  H=max_k F_k_nominal+1800 s。
所有客户交付、在班车辆完成责任并返库、全部出库机体随车入库均须≤H。不能仅因该车自有客户已送完，就忽略其接机、承运或返库责任而提前结束司机工时。H不能因某策略无解或发生第二次故障而延长。1800 s仍是全班余量，不是每个失败票各自的30分钟期限。

  c_km=8.57×14.9/100+0.40=1.67693元/km。
  c_depot=0.731012/0.90。
  c_vehicle=0.731012/(0.85×0.90)。
  C_elec=c_vehicle Q_net+c_depot Σ_d(E_cap-E_return,d)。
  C_var=c_km 全班车程km+C_elec。
  C_res=C_var+(105976/2088) 全班司机工时h。

Q_net是全班车载充电实际进入无人机电池的净电量，等于eta_slot乘以车载交流输出总量，同时包含行驶、合法停车和最终返库路段的实际充电。E_return,d取机体随实际承运车到库瞬间、仓库补电之前的余电；不能取末次R完成时余电代替。统一按满电出库、回库后补至满电的口径计算电费；回库补电只计费用，不推迟机体实际入库时刻。整班未出库机体无虚构耗电和补电。

司机工时从共同班次起点0到该车完成全部责任并最终返库的时刻计量；未出动车辆工时为0。自动充电可与DRIVE或人工地送并行，同一时段按实际经过时间计一次，不能把驾驶时长和重叠充电时长重复叠加。

成本按真实全班轨迹计算，第一次/第二次重排都不能重复收费历史前缀或丢失已付费用。没有F和场站收费。司机工时价值单列解释，不等同固定工资必然减少。

机载能量守恒：总机载消耗E_used=总初始机载电量+Q_net-总入库机载电量。由此：
  C_elec=c_depot E_used+(c_vehicle-c_depot)Q_net。
两种电费计算式应一致，避免重复收取机载补电或未使用的车载储能费用。

目标字典序：先min C_res，再在成本容差1e-4元内min全队最晚机体入库时刻z，其中：
  z = max_d t_return(d)；
  t_return(d) = T_depot(final_carrier(d))，对实际出库机体成立。
未出库机体t_return=0。不能用末票妥投或末次客户点回收时刻代替入库时刻。响应时间为报告指标，失败票按各自实际揭示时刻起算。同成本同z时使用固定结构ID等可复现规则消歧，不增加隐含业务目标。

本版没有把每票失败后的最短妥投时间列为主目标，因此只要物理条件和H允许，等待较长但全班成本更低的方案仍可能被选中。不得为了让结果偏向快速回收或复杂会合，偷偷增加等待罚项、强制异点接机或改变原车基准。若以后研究响应优先的服务目标，应作为另外的明确模型版本。

6.5  参数解释与敏感性分析边界

随机失效数量各取1或2、概率各0.5，是实验场景设置，不是估计得到的真实故障率。每车2机位、作业时长、供电参数、班次余量和费用系数均应与物理参照或研究假设分开标明。

载荷敏感性应逐段更新E_fly与P_h；等待敏感性应使用实际等待而不是新增固定秒数限制。若改变车速、机速、能耗系数、作业时间或充电条件，必须重新核验名义计划、H和执行前缀，不能只改恢复后缀以制造收益。

当前E_fly与P_h均按E_cap同比例缩放，E_min也按容量比例给出。因此，只改变battery_kwh而保持其他参考量不变，并不等价于在相同功耗下增大电池；它可能保持无充电SOC续航尺度基本不变。若单独研究电池容量，须另行区分能耗标定容量E_ref与实际可用容量E_cap，并作为新参数化版本说明，不能悄悄修改本版公式。

6.6  当前参数对求解设计的直接启示

以下结论由本文既定参数和成本公式推出，不是实际优化结果，也不增加新的运营限制。

（1）整车瞬时充电功率不必被夸大为当前最难的耦合。
每车最多2架无人机，每槽交流功率上限2 kW，整车上限4 kW。由于2×2=4，在占位约束满足且没有另外定义共享用电负载时，两架机各自按单槽上限充电并不会突破整车上限。该约束仍保留在模型与检查器中，以便以后参数改变；本版算法不需要为不存在的额外功率竞争另造复杂分配机制。
当前补能决策更关键的是：无人机何时在车且就绪、下一次何时放飞、实际承运车还剩多少交流电量，以及改变回收/放飞安排能否获得更合适的补能窗口。

（2）允许行驶充电，不等于所有可充时段必须充满。
沿用本文电费系数：
  c_depot ≈ 0.81223556 元/净kWh；
  c_vehicle ≈ 0.95557124 元/净kWh；
  c_vehicle-c_depot ≈ 0.14333569 元/净kWh。
若某机已经完成最后一次客户点回收、回收余电达标，之后不再飞行，且没有另外规定入库时必须满电，那么在纯返库路段增加净充电DeltaQ，不改变飞行消耗、入库时间或任务可行性，却使本文成本增加：
  DeltaC = (c_vehicle-c_depot)DeltaQ > 0。
在这些条件和当前目标下，到库再补电更便宜；因此最优安排可能不在最后的纯返库路段继续车载充电。这一推论不能写成“禁止返库路上充电”，也不能延伸为有后续航次时不应补能。算法应决定为后续任务补多少必要电量。

（3）提前放飞不一定改善完整方案。
提前放飞可能减少机上等待，却增加空中悬停，或缩短起飞前的在车补能窗口。较短的空中距离也不保证更低的全班成本。因此，最早时刻传播和飞行距离筛选只适合快速评价或有依据的下界，最终应联合核算放飞位置、充电、等待、回收与后续任务。

7.1  本版只实现这一套算法

  贪心插入与regret-2插入两种修复器；
  模拟退火接受准则；
  固定五起点与有界坐标模式搜索；
  固定结构下的时序、充电LP；
  按固定触发规则调用、最多重排6个相邻未来事件的局部MILP。

以上是同一个算法的不同职责，不是让开发者从六种算法中选择。ALNS选择修改哪些未来任务和怎样重新组合；插入修复器构造完整结构；连续搜索改变实际轨迹上的放飞位置；LP为固定结构和几何求时序、补能；局部MILP只调整其指定窗口内的事件顺序。局部数学规划的精确变量、约束及线性成立条件见本章数学契约段。

本版不实现强化学习、多臂老虎机、VND、遗传/模因算法、精英池、列生成、Benders、MCTS、情景rollout或CVaR。不得为了“增强算法”自行加入这些模块，也不保留运行时算法家族选择菜单。六个移除算子的普通ALNS权重更新不是强化学习。

S与X共用这一实现，只通过既有运营规则确定受影响航次的接收车辆资格。X的可选接收车较多，不使它获得更长计算时间、更大评价预算或额外隐藏信息。

下面全部超参数都是直接可运行的工程起始默认值，不是已调得的最优参数，不表示算法性能已经验证。开发者必须先按这些数值交付可运行版本；无需等待新的“待校准”决定。未来调参应另外登记实验配置，不能回看正式十个环境种子的结果后悄悄改默认值。

7.2  解表示、冻结边界与允许操作的域

一个结构包含三层，并使用稳定唯一ID。
  车辆层：每车的有序visit链；每次访问有独立visit_id和实际客户ID；访问内记录G/P/R/U等动作；纯支援访问可以重访已服务客户。
  无人机层：每架唯一无人机的真实持货、当前承运车、未来航次链、准备访问、实际放飞轨迹段、空送顺序、回收车辆与客户访问。
  依赖层：货物流、机体流、人工和通道操作、机位预留、实际运动以及充电资格事件。

“移除”只撤销计划安排，不撤销已发生的动作，不改变快照中的货物、电量、机位或承运关系。对一组订单改变安排后，必须同时撤销或重建已经失去作用的P/L/R/U、访问与依赖边，称为依赖闭包。闭包不得越过冻结边界；保留的已执行/不可撤销动作仍是真实约束。若某项改变只有越过冻结边界才能成立，该候选直接拒绝。

N_adj为当前允许调整的未交付订单数量，不含已交付订单、正在不可撤销地执行的交付和未受影响在途航次中被冻结的订单；不用作业符号U表示订单计数。目标移除规模为：
  r = uniform(0.10, 0.30)；
  q = min(N_adj, max(1, ceil(r*N_adj)))，仅当N_adj>0。
选择q个种子订单后做依赖闭包，实际牵动的订单或动作可能超过q；q不是业务上限。N_adj=0时不虚构移除订单，只求解和核验仍需完成的固定终端后缀。

全部客户点始终具有接机候选资格。下面的批次、窗口、迭代数和计算预算只限定本次搜索工作量，不能变成“仅最近K个点可以接机”、仅一票空送、仅一个新航次或仅一次换车的模型限制。

回收选择至少保留：原车或合格跨车、同点或异点、立即携带余货回收、继续全部可空送余票、继续任意可行子集后回收。现有失败票始终强制地送并继续真实占载。允许重复访问；支持先R、后U、再G的同点安排。任何正常/异常/末航次都必须在客户点回收到车上，再由实际承运车带回仓库。

恢复阶段仍保留已确认的局部调整范围：已完成和不可撤销动作冻结；未受影响在途航次冻结其承诺；保留地送的原普通任务维持原相对服务顺序；未来可调整任务只在真实货物和机体可达的范围内重新安排。名义阶段尚未出库，可以重新确定初始装车；恢复阶段不能把车上包裹免费搬到另一辆车。

7.3  名义计划的唯一初始化流程

名义求解完全不接收实际环境seed、实际M或隐藏失效客户，六张图各生成一次共同计划。

第一步：生成确定性的五车全地送初解。
  以仓库为原点，按atan2(y-y0,x-x0)、到库距离、customer_id升序排序全部客户；atan2取[-pi,pi)的统一实现。
  将排序序列连续分成5个尽量等长的区段；前N mod 5个区段多一个客户，按truck_id升序分配。
  每车从仓库出发，对本区段执行最近邻选点；距离并列时按customer_id；最后返库。每票执行G=50s。
  每辆实际出动车携带自己的初始无人机；不虚构P/L/R/U和飞行能耗。空区段的车和无人机不出动。
  对这份无需充电或空送决策的全地送路线直接前向计算：F_k=L_k/v_T+50*n_k，C_ground=c_km*sum(L_k)/1000+w_s*sum(F_k)；空车取F_k=0。构造完整时间表并独立核验，先取得C_ground。

名义阶段尚没有恢复时限H。为数学子问题提供的有限时间界固定为：
  w_s = (105976/2088)/3600，单位元/s；
  T_bound_nominal = (C_ground + 1e-4)/w_s + 1s。
因为全班所有费用项非负，任何成本不高于全地送初解的方案，其任一实际出动车的结束时刻均不会超过上述界。此界是保护改进解的数值搜索界，不是预先定义的恢复H。取得该界以后，再对同一全地送结构调用一次完整evaluate_structure并独立核验，与前向计算的时间、成本交叉核算；这次请求计入名义1000次总预算，避免“先有LP界才能求C_ground”的循环定义。名义最好解始终至少保留已核验的全地送初解；最终选定名义计划后才固定H=max_k F_k_nominal+1800s。

第二步：执行明确的空送转换启动阶段，不能跳过。
  该阶段最多使用100个额外完整评价请求；全部计入名义1000次总额，不另外赠送预算。
  对每辆至少有一个客户的车，先尝试1个单票转换；对至少有两个客户且存在总载荷不超过30kg的同车订单对，再尝试1个双票转换。
  单票种子按从当前地送链删除该G后可减少的行驶距离降序选取；双票先取原地送链中相邻、载荷允许的订单对，按联合行程节省降序。并列按订单ID。若相邻对均超过载荷，按订单ID枚举其他订单对，选首个允许者。
  P安排在删除订单前仍保留的最近一次合法访问，必要时为出库仓库；初始L若有准备后的真实行驶弧，固定先取第一条该弧ROAD；没有这样的弧才取该准备访问驻车期STOP。后续统一插入目录仍同时支持ROAD和STOP，不把此初始化顺序当合法性限制。回收初值为转换订单之后的下一次保留客户访问；若没有后续客户，插入一次转换订单最后一个客户的支援访问作为回收点。不得以仓库回收替代这个访问。
  每个转换结构按7.8的五个基础几何起点评价；本启动阶段不执行额外坐标细化，以保证先实际尝试各车的单票和双票结构。
  完成上述必做尝试后，按truck_id轮流扩展该车票数最多的已生成可行航次，并列按完整成本、sortie_id选择；按原地送次序选下一张仍未在该航次中且真实可装载的订单，跳过使载荷超过30kg者。尝试三票、四票及更多票，直到没有可加订单或该阶段预算用尽；每次仍由完整评价决定是否可行。这里没有人为票数上限。
  启动阶段保留最好已核验方案，也可继续以某个成本较差但物理可行的空送构造测试加票；成本较差的构造不能覆盖最好解。

后续进入固定ALNS，仍可生成新航次、增加多票、改变回收点和放飞路段。最终选全地送是允许的，但必须报告实际尝试的单票、双票、多票结构数、可行数和最好的空送成本；不得因为初始化只写了地送路线而声称无人机不划算。

7.4  实际失效后的热启动与无初解处理

每次收到同刻合并的公开观察后，先结算真实执行前缀并冻结，再从当前剩余计划开始。原计划中不存在的成功空送服务必须删除，失败票继续留在当前无人机上。

热启动候选采用固定的惰性枚举顺序：
  首先保留既有合法回收承诺并删除失败服务；
  然后枚举立即回收，以及保留全部尚可空送的原余票；
  再按保留票数从少到多、订单ID字典序枚举其他余票子集。相同子集不重复；空子集和全集不再重复出现。
每个子集最初保留原航次相对顺序，后续ALNS允许对受影响且可调整的订单重插。回收车辆按S/X资格生成；客户、支援插入位置都来自完整合法域。初始优先次序为原接机承诺、同点回收，随后用7.5代理增量排序，其余候选持续通过游标展开，不能删去其他合法客户。

对未空送的当前机载货物补上真实R/U及之后的地送/未来合法处理；对仍需配送的其他订单调用两种固定修复器，初始尝试按“贪心、regret-2、贪心、regret-2……”交替。每个完整结构才进入完整评价和核验。没有全班可行候选时，不能把部分完成的结构当初解。

没有可行初解时，尚无SA工作解，也不设虚假的巨大成本。继续以上有界构造、候选域游标展开和规则触发的局部顺序MILP，直到获得可行初解或总预算耗尽。20轮没有最好解也计为20轮停滞，允许触发局部MILP。各次构造计入共同轮次与计数，不免费重试。

局部MILP没有模式选择或货物重分组能力，不能被描述成“自动修复任何路线不可行”。它只尝试修复当前已构造完整结构中的局部事件顺序；改变回收客户、车辆、余票子集仍由外层构造负责。

始终未取得完整可行解时返回NO_SOLUTION_LIMIT，并记录检查过的候选和停止原因。某个初始结构、固定全序LP或6事件局部MIP无解，均不能推出整个恢复问题INFEASIBLE。只有独立有效的全域不可行证明才能使用INFEASIBLE；本启发式通常不产生这种证明。

7.5  两个固定插入修复器及唯一代理分数

修复器只用确定性的结构代理分数挑选插入，避免为每个尚未完成的部分计划反复调用完整LP。所有最终接受和报告的真实成本仍来自完整评价。

对一个构造中的部分结构P定义：
  C_hat(P) = c_km*L_T(P)/1000
             + w_s*[L_T(P)/v_T + 50*n_G + 30*n_P + 30*n_R + 20*n_U]
             + c_depot*E_air_no_wait(P)。
L_T为所有已构造车辆后缀行程的米数；各n按已构造的真实动作计数，U按批计；L自动进行，不加入司机人工时长。E_air_no_wait使用第6章真实载荷能耗公式，计巡航、L、R和已计划成功空送的60s服务，但不假定任何空中等待或车载充电；实际已携带却尚未指定交付的机载货物仍计入载荷，不能从部分结构中消失。

代理中的几何取同一实际弧上的既有lambda；没有可继承lambda时取弧中点0.5；驻车L使用真实客户/出库仓库位置。代理仅覆盖还未发生的后缀，已发生历史成本是常数。插入代价为Delta_hat=C_hat(P_after)-C_hat(P_before)。

该代理不包含同步等待、实际充电费用和资源竞争，不能当真实业务目标、能量可行性结论或全局下界。代理分数低的候选仍可能被完整评价否决。

统一插入目录至少支持以下固定动作族：
  G_INSERT：将实际可由某车持有的订单插入该车合法访问间隙或同客户已有未来访问；遵守保留原地送任务的相对顺序。
  AIR_INSERT：插入已有未执行可调整航次的任意空送位置，或新建真实可装货的航次；通过反复插入形成任意载荷允许的多票航次。
  RECOVER_UNLOAD_INSERT：为实际在空中的机体及机载货物联合补入R/U、接收车访问及后续G；接收车资格遵守S/X。
  SUPPORT_INSERT：为P或R插入/移动客户支援访问，可重访任一客户；一项订单插入可以带上必需的支援动作闭包。
每次构造也枚举合法驻车L和P之后的各段真实行驶弧。L完成位置必须在实际轨迹上；候选不能要求货物瞬移或使用冻结动作之前的位置。

目录采用惰性生成，不能一次性构造全部笛卡尔积。每次给一张待插订单最多保留64个通过结构检查的插入候选，单次扫描最多512个原始候选。对接收客户采用稳定ID轮转：候选先在所有客户之间轮询，再继续该客户的其他车/访问间隙/放飞弧组合；每个公开快照、订单和动作族保存展开游标，下一轮从未完成位置继续，而非永远重看最近的64个点。几何距离或代理分数只决定先检查的顺序，不能改变目录成员资格。

结构检查可剔除明确错误：冻结冲突、真实持货不符、超过30kg、非法接收车、非客户接机、重复交付、实体流断裂和必然正时长因果环。尚未求出的充电/等待不能按启发式估值宣布不可行。

R1：全局最小代理增量贪心。
  每轮对各未插订单得到当前批次的最低Delta_hat；选择全体中最小者，应用其整个动作闭包，然后重算受影响的候选。
  并列依次按order_id、候选结构ID消歧。

R2：regret-2。
  对每张订单保留当前批次中两个不同结构的最小代理增量delta1<=delta2；存在两个时regret=delta2-delta1。
  仅一个可插候选的订单优先于所有有两个候选的订单；这组内部按delta1、order_id排序。
  其余按regret降序、delta1升序、order_id升序选择，再插入其delta1候选。
  当前批次没有候选的订单暂缓，不计算inf-inf。若所有剩余订单本轮均没有候选，则结束此次修复，记REPAIR_BATCH_EXHAUSTED；下一轮继续目录游标，不声明业务无解。

每次成功插入至少安置一张尚未安置的订单，最多进行原移除池大小次成功插入。应用联合闭包时可能一并安置多张订单，应同步从池中移除。没有完整安置所有订单的中间结构不得进入SA，也不得被执行。

7.6  六个固定移除算子

D1 RANDOM_DEPENDENCY：对N_adj张可调整订单均匀无放回选q张，再做依赖闭包。

D2 AFFECTED_SORTIE：优先选当前公开故障所涉机体的受影响航次及其后续可调整航次中的订单；同一链内按实际/计划执行先后，链并列按最近公开故障时刻和drone_id。没有受影响链时，选择最早未执行航次。该组不足q时从其他可调整订单均匀补足；超过q时先取前q个种子，再做闭包。失败票不会因此变回空送允许。

D3 RENDEZVOUS_RESOURCE：按当前已核验方案各未来R的“无人机到场至R开始等待+车辆到场至R开始等待”降序选择一个回收锚点；并列按event_id。在与该R共用接收车、无人机或通道的可调整订单中，按计划作业时刻到锚点的绝对差排序取种子，再从其他订单补足。该算子放开相关可调整回收/访问安排，冻结承诺仍不动。

D4 ENERGY_CHAIN：按未来航次回收结束的E-E_min升序选最紧张航次；并列按drone_id和sortie_id。选该机可调整航次以及相关接收/补能车辆上的邻近未来订单，按到锚点的时差取种子，不足时补足。只改变可调整结构，不改当前电量和车载供电余额。

D5 SUPPORT_VISIT：选择额外车辆绕行距离最大的纯支援访问，绕行量为d(prev,j)+d(j,next)-d(prev,next)，并列按visit_id。移除或重新关联其所支撑的可调整P/R及订单，允许在其他任意客户重新插入支援访问；若该访问含冻结动作则不选。没有可调整支援访问时回退D1。

D6 SORTIE_REGROUP：在未开始且可调整的航次中，按sortie_id排序后用算法随机流均匀选一个锚点；移除其订单，并从该机相邻未来航次或实际同车可用订单补足q。修复可以合并、拆分、改地送或形成更多航次；只受真实载荷/资源和预算约束，没有“最多再加一票”的上限。没有这样的航次时回退D1。

各算子“补足”统一为对尚未选中的可调整订单均匀无放回抽取。无适用锚点的D2/D3/D4也回退D1。回退记在实际所选算子的使用次数中，并另记fallback次数；不能让未产生动作的算子免费重抽到成功为止。

放飞弧的选择由统一插入目录负责；实际lambda由7.8负责，不再增加第七个算法名称不清的移除器。

7.7  自适应权重、真实目标比较与SA

移除组6个权重、修复组2个权重独立维护，全部从1.0开始。每轮分别按w_i/sum(w)轮盘选择一个移除器和一个修复器，不使用学习模型。

每25个ALNS外层迭代更新一次权重；初始热启动尝试不更新算子权重。记录每算子的使用次数n_i和奖励和s_i，更新：
  若n_i>0，w_i=max(0.1, 0.8*w_i+0.2*s_i/n_i)；
  若n_i=0，w_i不变；
随后清空这一段的n_i、s_i。移除/修复对获得同一份奖励，各算子的每次使用只计一次。

奖励只取一种最高适用等级：
  33：产生新的最好已核验解；
  9：未破全局最好，但严格改善该轮开始的工作解；
  3：其他已核验候选被SA接受；
  0：未被接受、构造未完成、评价失败或核验失败。
哈希完全相同的候选或只因结构ID较小而消歧的候选不算改善；不因缓存命中给额外奖励。一次轮次中MILP或连续细化产生的改进归于该轮选中的算子对。

真实比较使用第6章C_res与z，不用代理分数：
  C_A<C_B-1e-4时A优；
  |C_A-C_B|<=1e-4时，z_A<z_B-1e-3才按z改善；
  两者都在容差内时用稳定结构ID消歧。
保存不含运行时间、随机UUID和内存地址的规范化结构ID；同一业务结构应得到同一ID。容差只是数值比较，不给失败票增加服务时间目标。

各次搜索的初始温度在取得首个可行工作解时固定：
  C_scale=max(C_initial_full-C_prefix_fixed,1.0元)；
  T0=-0.01*C_scale/ln(0.5)。
C_prefix_fixed使用第6章守恒电费形式结算已发生车程、已耗机载能量、已发生净车充和截至快照的司机工时，是所有候选相同的真实常数。名义求解C_prefix_fixed=0。不得用随故障时刻不断增长的历史常数放大退火温度。

名义/确定性计数模式的进度p取已用完整评价数/总完整评价预算；在线模式取自本次调用起已用墙钟时间/60s；截断到[0,1]。温度为：
  T(p)=T0*0.01^p。
只初始化一次T0；不因停滞、MILP调用或再次得到可行解而重新升温。下一次真实故障是新的求解调用，可按新的公开快照初始化。

SA规则固定为：
  真实字典序改善或两目标都在容差内的可行候选接受；
  成本差在±1e-4内但z更差的候选拒绝；
  成本变坏超过1e-4的可行候选，以exp[-(C_candidate-C_current)/T]接受；
  不可行、未完成或未核验候选永不进入工作解。
退火只对真实成本劣化起作用，不另加时间罚项。概率计算超出数值安全范围时直接视为0，不修改成本。

最好解和工作解分开存储。最好解按真实目标更新，绝不随SA回退；最终返回最好已核验解，而不是最后工作解。成本容差内的z优化使用数学段的两阶段约束，禁止反复利用1e-4容差累计抬高成本。

为正确处理容差的非传递性，只为结果比较维护cost_band_records：保存迄今最小已核验原始成本C_min_seen，加入每个新核验候选后更新该值，删除C>C_min_seen+1e-4的记录；令z_min为当前成本带记录中的最小z，在z<=z_min+1e-3的记录中按稳定结构ID选择最好结果。可删去在成本和z上同时被另一记录支配的记录。保存记录须能恢复对应完整计划，不能只留下数字。该成本带记录只保证正确选择最终结果，不能被抽样、交叉或当作新搜索起点，不是另加搜索精英池。若C_min_seen下降使旧最好解超出成本带，应从仍在带内的所有记录重新选取，避免丢失先前已发现的较快候选。

7.8  唯一连续位置算法

实际客户驻车期的L没有虚构的道路lambda；位置固定，L时刻由LP在合法访问内选择。道路上L以“L完成、机体离车”的实际轨迹段和lambda表示。禁止额外要求L开始与L结束必须位于同一条弧；动力L可以跨过合法访问/相邻道路弧边界，只要其全部10s在车辆真实轨迹和通道/准备约束下可执行。

每个尚可调整的道路放飞lambda有合法范围[lo_j,hi_j]；已经经过的轨迹不可选。将可调整分量归一化为theta_j=(lambda_j-lo_j)/(hi_j-lo_j)。hi=lo的固定分量不参与坐标搜索。

每个完整结构的基础起点按下列唯一向量序列生成：
  B0：同一实际弧和同一航次可继承的既有lambda，裁到合法范围；新弧/新航次取该合法区间中点；
  B1：全部可调theta=0；
  B2：全部可调theta=1；
  B3：全部可调theta=0.25；
  B4：全部可调theta=0.75；
  B5：全部可调theta=0.5，仅用于补足。
按上述顺序去除完全相同的向量，取前5个不同向量；没有可调lambda时只评价一次。已有解B0也计一次请求，不能额外免费评价。多个放飞点使用同一向量模板，不由开发者随意选择某几维组合。基础五点是搜索起点，不是允许放飞点集合。

每个起点调用evaluate_structure时传event_order=None，让数学段按新几何重建参考全序；不能沿用旧全序人为禁止L跨过别的事件。一个起点LP不可行只说明该起点与所建全序未求得可行，不证明整段连续轨迹不允许。

额外坐标细化只在以下任一条件成立时执行：
  当前结构基础起点产生了比本次调用已有最好解更好的可行候选；
  已有工作解且ALNS外层迭代号为10的倍数。
启动阶段结束时对其最好解执行一次同样的细化。预算不足则跳过并记录，没有免费尾部优化。

每次细化最多新增40个完整评价请求，基础起点评价另计且同属总预算。初始步长h=0.25；一轮所有坐标均无改善则h减半；h<1e-3时该起点停止。每个起点各有当前向量、h和轮次状态；按基础评价的真实优劣排序后轮流进行一组坐标正负试探，未可行起点排在后面。对当前坐标尝试clip(theta_j+h,0,1)与clip(theta_j-h,0,1)，比较两者和当前点，保留最好可行者；由不可行点找到可行点即成为该起点的工作点。两个方向都不能得到可行者则保持原点，不把不可行点作为可执行解。

坐标按稳定launch_id排序，并以当前ALNS迭代号mod维数循环偏移起始坐标，避免反复只细化前几个放飞点。完成一轮坐标后，若有改善则保持h继续，否则减半。五个起点均达到步长阈值或40请求/总预算耗尽时结束；始终保留已核验最好位置。

收缩到1e-3是本次局部位置搜索的停止条件，不表示数学全局最优，也不是把道路永久划成0.001网格。若先耗尽40次预算，应记录COORDINATE_LIMIT，不能谎称位置已经收敛。所有最终距离按实际坐标重新计算。

7.9  局部MILP的唯一触发和职责

局部MILP只使用本章数学契约定义的最多6个相邻尚未执行事件窗口，固定车辆/货物/航次结构、载荷与几何，重选该窗口内允许改变的事件先后。它不是第三种插入修复器，也不选择新增运营策略。

维护包含初始修复在内的round_index，以及“连续没有改善最好解的轮数”stagnation。满足以下条件才调用：
  (round_index mod 25==0 或 stagnation>=20)，并且
  距离最近一次MILP调用至少5轮，并且仍有预算。
第一个条件的25表示结构搜索轮次，不是LP调用次数。首次调用没有间隔限制。一次调用之后，无论成功或失败，都更新last_mip_round，避免停滞后每轮重复调用。

有完整待评结构时优先处理本轮候选；否则处理当前最好完整结构；没有任何完整结构则不调用并记录NO_COMPLETE_STRUCTURE。本轮存在多个几何评价时，若有可行解，取本轮真实目标最好的那个位置及其已构建全序；若全部不可行，按基础起点B0至B5的生成顺序取第一个已经成功构建event_order的评价。全部没有全序则返回NO_EVENT_ORDER，不凭空添加一个MILP模型。窗口按数学段固定规则选择，不能随机扩大到全班整数规划。

生产在线单次MILP的墙钟上限为min(2s,扣除最终核验保留后剩余时间)，节点上限node_limit=1000。调用返回新的全序后，必须再执行一次完整固定全序LP评价并通过独立核验；这一请求计入总评价预算。局部MILP内部候选、最优间隙和终止状态另外记录。找不到改进或可行全序不无限重试。

名义计数模式与确定性回归模式使用同一node_limit=1000，不用2s墙钟截断；固定软件版本和矩阵排序。SciPy公开milp接口没有本规范可依赖的random_seed/threads参数，不能虚构已设置这些选项。版本固定也不构成跨平台逐位一致保证。

7.10  统一评价入口、预算和停止规则

唯一完整评价入口：
  evaluate_structure(state, structure, lambda_vector, event_order_or_none, context)
它负责固定候选的完整时序、能量、充电和成本求解，返回求解状态、真实目标、完整动作计划、计数和诊断。独立检查器必须重算结果后才允许写入工作解/最好解。

进入该入口即计1个eval_request，包括缓存命中、LP不可行、数值失败及超时。每次请求包含的参考构序LP、成本LP、成本带内的z优化LP分别记录solver_calls；不能把这几个阶段各冒充一套额外候选预算，也不能把无限内部求解藏在一次请求里。详细数学契约规定初始全序构造与两阶段优化。

基础几何起点、额外坐标探测、MILP输出回验、名义全地送初解、空送转换和恢复初始构造的完整评价均计入同一eval_request。廉价代理计算、结构筛选和候选扫描另计次数；它们不产生已核验解。完整结构缓存的键至少包含公开快照哈希、候选结构、全部实际几何、明确全序（或构序版本）、参数版本和策略资格；不能跨不同货物/电量快照复用结果。

默认预算：
  名义：1000个完整评价请求，最多2000个结构搜索轮次；不另给初始化、MILP回验和连续细化额外预算。
  正式恢复：每次调用总墙钟60s，从输入校验开始计时，含构造、全部LP/MILP、连续细化、检查、日志和结果返回；进入最后2s后停止新增搜索，核验并返回已保存最好解。
  确定性回归/计数基准：每次恢复1000个完整评价请求，最多2000个结构搜索轮次；不启用墙钟停止；MILP节点上限1000。
  三种模式均设max_search_rounds=2000，防止大量廉价拒绝在没有消耗评价次数时无限循环。

在线每次内部LP/MILP开始前重新计算剩余时间并传入可用上限，不允许先启动一个无限制子求解器再在外层宣称60s截止。完整检查器应对当前数据规模有明确有界遍历；不能在最终2s内重新进行昂贵搜索。最好解在搜索过程中已经完成核验，末尾检查快照版本和输出一致性，未核验的新候选不能覆盖它。

必须输出：n_search_rounds、n_alns_iterations、n_initial_repair_rounds、n_eval_requests、n_eval_by_reason、n_base_geometry_evals、n_coordinate_evals、n_mip_return_evals、n_lp_reference、n_lp_cost、n_lp_secondary、n_mip_calls、n_mip_nodes、n_verifier_calls、n_proxy_scores、n_generated_insertions、n_fast_rejects、n_cache_hits，以及初次可行解耗时、总耗时和停止原因。
每个完整请求的reason只能取下列互斥枚举之一：NOMINAL_GROUND、NOMINAL_AIR_BASE、RECOVERY_INITIAL_BASE、ALNS_BASE、COORDINATE、MIP_RETURN。n_eval_requests=sum(n_eval_by_reason.values())必须严格成立。n_base_geometry_evals是后三类基础几何NOMINAL_AIR_BASE+RECOVERY_INITIAL_BASE+ALNS_BASE的派生和；n_coordinate_evals和n_mip_return_evals分别由其对应reason派生，不能将这些派生统计再与reason计数相加。各solver_calls是内部工作量统计，也不与eval_requests重复相加。名义1000是请求上限，不强迫在已经没有可调整任务时制造1000次重复评价。

生产在线墙钟模式不承诺不同机器逐次选择完全相同；严格回归比较使用固定评价/节点预算模式，并锁软件版本、输入排序和随机流。正式S/X仍统一用60s模式，计数模式不能冒充已经测得的实时求解结果。

7.11  算法随机数与信息隔离

正式算法基准seed固定20261111，与十个环境seed是两套独立配置。
派生过程固定为：
  text = "tdr_v61|" + str(base_algorithm_seed) + "|" + case_id + "|" + phase + "|" + str(replan_index) + "|" + stream_name；
  seed = int.from_bytes(SHA256(text.encode("utf-8")).digest()[:8], "big")；
  使用Python random.Random(seed)。
phase只取nominal或recovery；名义replan_index=0，恢复从1开始按实际公开重规划调用累计。stream_name固定为operator、destroy、accept三个流。插入目录、几何起点和坐标顺序是确定性的，不另抽随机数。

派生text不含strategy，S/X在相同case和相同观察序号使用相同初始算法流；实际状态/搜索路径不同可造成后续随机数消耗不同，不承诺逐次动作相同。派生text绝不包含environment_seed、真实M、隐藏名单或它们的哈希。规划器接口也不接收这些私有字段。

正式稳定性补充实验按项目契约分别用20261111、20261112、20261113作为base_algorithm_seed，直接使用上述同一公式。这是固定的补充重复，正式主结果仍为20261111。保存随机流状态和公开输入哈希便于调试，不以环境seed“复现算法”。

7.12  完整主流程

输入：公开快照、剩余计划、S/X资格、公开物理配置、case_id、观察序号、固定算法配置、预算模式。

1. 启动总预算计时/计数；校验公开接口、冻结边界和实际持货；创建三个独立算法随机流。
2. 名义模式构造并核验全地送初解，按7.3执行空送转换；恢复模式按7.4修复原剩余计划。
3. 无可行初解时持续生成下一完整候选、评价并按规则尝试局部顺序MILP；在预算内找到初解才初始化SA。
4. 已有可行解后，按权重选1个D和1个R；根据q种子和依赖闭包生成移除池，调用固定修复器。
5. 候选完整才做基础五几何评价；不完整记失败。本轮按7.8触发额外坐标细化，按7.9触发局部MILP；全部完整请求使用同一总预算。
6. 独立核验返回计划；按真实目标维护最好解，按SA维护工作解；记录唯一奖励，更新停滞和25轮算子段统计。
7. 达到评价、墙钟、轮次上限或已无可调整任务时停止，返回最好已核验方案及诚实状态。
8. 仿真器执行真实后缀；若以后出现新的实际观察，从该策略自己的真实状态再次调用，不重置成本、电量、货物和H。

本版采用既定虚拟时间即时决策主实验：decision_latency_s=0，60s只是求解器墙钟计算预算，二者分开记录。不得冻结真实时间却扣一次虚构60s悬停，也不得以本实验自动声称部署中计算耗时没有影响。纳入真实决策延迟属于另一个明确实验，不在本版主实现中自行添加。

7.13  唯一允许的固定消融配置

主实验algorithm_variant固定full。只实现以下三个单项消融开关，供项目契约的消融命令调用：
  uniform_weights：六移除、两修复和其余模块不变，所有权重始终为1，不更新奖励权重。
  no_coordinate_polish：保留每个完整结构的基础五几何起点评价，关闭额外坐标细化。
  no_local_mip：关闭局部6事件顺序MILP，其他全部不变。
不组合开关，不增加其他算法家族。四种配置用相同数据、预算、真实成本、信息规则和核验要求；不因关闭一个模块另赠预算。消融改变搜索范围/用法，不改变全部客户可接机、连续轨迹可放飞等原业务规则，也不提供全局最优证书。

以上清单与本章流程、数学契约和配置文件应一一对应。工程默认值直接生效，不再出现algorithm=auto、solver=choose_best、待决定是否使用MILP或待决定选择遗传算法等分支。参数数值的合理性最终由同模型、同预算、经独立核验的实验检验；本规范锁定的是可实现的第一版方案，没有提前宣称它优于其他算法。

7.15  固定结构时序充电LP与局部事件重排MILP

本节是开发规范，不是另一套运营模型。外层已经决定客户访问、包裹方式与顺序、机体、实际持货关系、接收车和接收客户访问、P/R/U/G 所属访问、L 结束所在轨迹区段，以及道路弧上的连续位置 lambda。本节在这些条件固定后，联合计算时刻、等待、电量和充电。局部 MILP 仅放开相邻至多 6 个未来事件的全局排列，不改变这些几何、载荷和任务条件。局部最优与原联合问题的全局最优必须区分。

一、唯一技术栈、接口与求解器选项

Python 3.11+；NumPy 与 SciPy；连续子问题只使用 scipy.optimize.linprog(method='highs')；局部整数子问题只使用 scipy.optimize.milp，底层均为 HiGHS。不增加 Gurobi、CPLEX、OR-Tools、其他 NLP 求解器或候选整结构模式池。

固定公开接口：
  evaluate_structure(state, structure, lambda_vector, event_order, context) -> Evaluation
  local_reorder_mip(state, structure, lambda_vector, event_order, window_start, context) -> ReorderProposal

event_order 为 None 时先按第七部分构造全序；非 None 时按传入全序评价，不能偷偷重新排序。structure 必须是包括所有未完成任务、真实回收与最终随车返库的完整后缀，不接受只有少数插入任务的残缺候选。lambda_vector 按稳定 launch_id 排列。新 lambda 试点传 None 重新构序；MILP 输出的全序回验时显式传入该序。

linprog 固定 options：
  presolve=True；disp=False；
  primal_feasibility_tolerance=1e-7；
  dual_feasibility_tolerance=1e-7；
  ipm_optimality_tolerance=1e-8。
生产恢复时，每次内部 LP 前重新读取整次恢复剩余预算，time_limit 取扣除最终独立核验预留 2 s 后的剩余秒数；没有正的可用时间即停止。名义计数模式不设置 LP 墙钟截断。不要给每个内部 LP 重新发放完整 60 s。

milp 固定 options：presolve=True，disp=False，node_limit=1000，mip_rel_gap=0.0。生产在线恢复模式一次 local_reorder_mip 的建模、两阶段整数求解及结果提取共用至多 2 s 预算，并受整次恢复剩余预算约束；调用每阶段时更新 time_limit 和剩余 node_limit。回归计数模式关闭 2 s 墙钟截断，保留一次调用累计 1000 个节点上限。后续 LP 回验另计一次 evaluate 请求，并仍计入同一次恢复总预算。

SciPy 的公开参数名为 node_limit，不能写 max_nodes。公开 milp options 不包含 random_seed、threads，也不提供 x0 热启动参数；本版不依赖未公开透传设置。固定 Python/NumPy/SciPy 版本、输入矩阵和事件排序、ALNS 随机流，关闭回归测试的墙钟截断，用来减少重复差异；不承诺不同平台或不同版本位级一致。外部保留已核验 incumbent 作为超时退路，不能声称把它作为 SciPy milp 的热启动解传入。

一次 evaluate 请求计 1 个候选预算单位。新全序可能实际调用三个 LP：参考时间 LP、成本 LP、末次机体入库时间 LP；指定全序时最多两个。内部 solver_calls、耗时、状态另行完整记录，不能把内部 LP 说成没有计算成本。局部 MILP 的两个阶段共用一次调用预算，不各自重新获得 2 s 或 1000 节点。

二、输入必须先冻结的对象与有界时间域

每个客户访问用 visit_id 区分，重复访问不能合并。每个实际机体用 drone_id 区分。每票的保管者、装载、卸货和交付事件必须显式存在。外层先核验一次交付、库存流、载荷不超过 30 kg、策略 S/X 的接收车资格、全部客户点可接机、已有行动冻结、最终客户点回收后随车入库。发现结构违反这些条件即拒绝，不用时间 LP “修复”货物流。

几何和阶段载荷均先计算成常数：道路距离、L 结束位置、各空中航段距离、每段巡航载荷、每段悬停/服务/L/R 载荷。不能把可变质量 m 代入 28000-400m 的分母后仍称为 LP/MILP；不能让局部 MILP 同时选择客户顺序、连续坐标和载荷。

令当前快照绝对时刻为 t0；内部未来时间变量采用相对秒 u_e=t_e-t0。已经执行完的事件删除为历史常量；正在执行的不可撤销动作以剩余时长、剩余距离、当前余电和已占资源进入后缀。历史电耗、服务时长和已花成本不能重新计算第二遍。快照中已经在 R 的机体，其机位预留必须已经计入初始占位；已开始 L 但未结束的机体仍占机位。

恢复阶段 B=H，其中 H 只能来自已完成核验的共同名义计划：H=max_k F_nominal,k+1800 s。第二次失败不能重新延长 H。令 Tspan=B-t0；未来所有事件时刻和全局间隔端点落在 [0,Tspan]。

名义阶段尚无 H，先构造并核验全地送方案，取得其完整班次成本 C_ground。用
  B_nominal=(C_ground+tol_cost)/wage_per_second+1 s，tol_cost=1e-4 元，
作为名义子模型的有效数值界。完整成本各项非负，任何比全地送更好的方案都满足每车 F_k<=B_nominal。此界用于数值线性化及保留优于已知可行基线的搜索范围，不是新的班次时限，不是先验 H。最终名义方案产生后再生成并冻结 H。

若恢复时 Tspan<0，则当前 H 下没有未来完成空间；不得换用名义 B 或临时扩大 big-M。若只因启发式候选或局部窗口失败，不能据此宣告原恢复问题不可行。

三、物理事件、连续放飞和时间约束

至少建立以下边界事件：快照、车辆各访问到达/离开、G/P/U 的开始/结束、L/R 的开始/结束、无人机飞行出发/到达、成功空送服务开始/结束、等待阶段起止、充电资格阶段起止、各车最终到库。一个物理瞬间同时承担多个阶段边界时使用同一 event_id，或者用等时关系加明确因果边连接；禁止仅因重复命名虚构一段额外时间。

每车相邻访问 v,w 的固定道路距离为 D_vw：
  t_arr(w)=t_dep(v)+D_vw/v_T。
车辆不能通过拉长这条等式隐含在非客户点停车。可以选择的停车等待只进入合法客户访问的 t_dep-t_arr；首次出库和最终入库按既有仓库边界处理。司机人工 G/P/R/U 都必须完整包含在其所属合法停车访问内：
  t_arr(v)<=s_a，f_a<=t_dep(v)。
未出动车辆 F=0；已经完成返库的车辆 F 保留为历史常量。

固定作业时长：G=50、P=30、L=10、R=30、U=20 s；成功空送服务=60 s。使用 f_a=s_a+tau_a。U 按一次异常回收批量执行，不按剩余包裹数重复 U；每票真实地送各计一次 G。

上面的完整时长等式，以及下文 s_L=t_Lend-10，只适用于尚未开始的新动作。已开始动作的历史 start 不建成要求非负的未来变量；其未来 end 按快照固定为剩余时长，能耗只扣剩余部分。例如 L 已执行5 s，则其未来 L_end 为5 s，不再生成 s_L=-5 s 的非负变量，也不再扣完整10 s电量。正在执行的 P/R/U/G、空中服务和巡航同理；巡航按当前位置到不可撤销目标的剩余距离续算。若需要历史 start 参与日志或等式，它只能是允许小于0的历史常量。

每次 L 的结束模式只能是外层已选定的 ROAD 或 STOP：
  ROAD：选定真实道路弧 v->w 及固定 lambda∈[0,1]，
    x_L=(1-lambda)x_v+lambda*x_w，
    t_Lend=t_dep(v)+lambda*D_vw/v_T；
  STOP：选定实际停车访问 v，x_L=x_v，
    t_arr(v)<=t_Lend<=t_dep(v)。
初始仓库可以承担已有模型允许的出库准备/放飞，最终入库不是可额外重启的中途访问。以上 STOP 不新增任何非客户停车点。

统一 s_L=t_Lend-10，f_P<=s_L。不要加 s_L>=t_dep(v)；L 可以从前一停车段或更早的道路段开始，并跨越道路弧边界。机体在 L 结束前都实际随车，L 结束位置由所选结束区段确定。既定实际轨迹在 10 s 期间的移动不计为独立空中巡航。

若车当前已在该道路弧 lambda0 处，新决策的离车位置不能位于已驶过部分；对仍不可撤销地行驶的当前弧，可直接写相对 t_Lend=(lambda-lambda0)D/v_T，且新开始 L 必须 s_L>=0。已开始 L 的剩余过程和离车位置按快照冻结，不能重新选择 lambda。一般后续区段仍使用 x_L=x_truck(t_Lend)；不要求 L 的开始与结束属于同一段。

固定空中航段 a->b：
  t_arr(b)=t_dep(a)+ell_ab/v_D。
允许空中等待时，另设 w=t_next_start-t_arr>=0，并按真实载荷扣悬停能耗；不能把等待藏在飞行速度中。失败客户不执行成功空送的 60 s，也不卸货；已知失败票只能通过真实异常 U 后安排 G。成功服务的包裹在服务结束时卸载，随后阶段才减少质量。

回收客户访问必须是真实 customer_id 对应的 visit_id，包括失败客户及重访客户。R 开始同时满足车辆到场、无人机到达、通道可用、司机可用和空机位可预留：
  s_R>=t_arr_truck(v)，s_R>=t_arr_drone(v)，f_R<=t_dep(v)。
异常批次 s_U>=f_R，f_U<=t_dep(v)。要在同一失败客户直接改地送时，货物交接与地送有 f_R<=s_U、f_U<=s_G；不能在回收前虚构地面完成。后续 P 若使用该批货物，同样必须在相应 U 完成之后。

每个出库机体最后的物理状态必须是在实际承运车上。已独立飞行者必须存在真实最后客户点 R，之后持续占位直到该车最终入库；若后来再次 L，则还需新的客户点 R。始终未起飞但随车出库者可以直接随车入库，不虚构 R。不得加入无人机直飞仓库、独立落地免费等待或仓库接机的后门。

四、每架机自己的阶段能量链

按该实体机体的真实先后建立连续能量链，阶段端点电量为 E_d,j，取 0<=E_d,j<=E_cap。当前首端点固定为快照余电。每个阶段恰好采用下列一种更新：

  巡航：E_next=E_prev-Efly(ell,m)，
    Efly=beta_cruise*E_cap*ell/(28000-400*m)；
  动力 L、动力 R、成功空送服务或空中等待：
    E_next=E_prev-Ph(m)*(t_end-t_start)/3600，
    Ph(m)=beta_hover*(P0+(P30-P0)*m/30)，
    P0=E_cap/(29/60)，P30=E_cap/(18/60)；
  可充电阶段 b：E_end(b)=E_start(b)+eta_slot*sum_h q_bh；
  在车但本机 P/U 等不充电阶段：E_next=E_prev。

L/R、服务、等待阶段的载荷是各阶段真实未卸载包裹总质量，不以平均载荷替代。每个 R 结束要求 E>=0.10*3.9688 kWh。异常回收的失败票和其他未交付票在 U 前仍在机上；从 R 结束开始不再扣悬停能耗。任何阶段中都不得负电量，不能仅检查整航次或全班净能量。

充电阶段 b 是“同一架机、同一实际承运车、连续具备本机充电资格”的最大时间段，其起止使用确定的事件身份。正常 R 后到本机下一次 P 开始可形成一段；P 完成后到本机 L 开始是另一段；异常 R 必须到 U 完成才开始充电。其他机体的作业、司机为其他包裹 G 和车辆 DRIVE 不打断本机充电资格。回收/交接后额外充电就绪延迟固定为 0 s。

本机 P/L/R/U 都不充电；空中巡航、服务、悬停等车不充电。准备完成而尚未 L 的 READY_ON_TRUCK 可以充电，直到 L 开始。最后随车返库段保持同一规则，是否充电由成本和后续需要决定，不强制充满，也不禁止充电。

不能仅用 q_dh 按机体和全局时段记账后把全班能量汇总。必须使用 q_bh，以充电阶段 b 区分同一机体的前后多次充电，且把各 sum_h q_bh 只接入它自身的阶段能量链。这样后一次回车的电不能借给前一次飞行。

阶段内耗电单调下降、充电单调上升；各耗电阶段固定功率或固定巡航几何，分阶段端点电量检查可覆盖内部时刻。输出执行计划时还需逐全局间隔重建充电和余电账本，独立检查器不能只信任 LP 的端点标签。

五、固定全局事件序下的 LP

令固定全序为 e_0,...,e_M，各事件相对时刻为 u_e，按序令 tau_h=u_(e_h)，h=0,...,M；
  delta_h=tau_(h+1)-tau_h>=0，h=0,...,M-1。
不同事件可以同刻，零时间间隔合法。事件先后因果边必须与全序相容，不能为迁就排序删掉因果边。

对每个充电阶段 b，已知 start_b、end_b 及 k(b)。令
  chi_bh=1 当且仅当 rank(start_b)<=h<rank(end_b)，否则为0。
q_bh 单位是该阶段在该全局间隔内消耗的车载交流电量 kWh，而不是功率和净入电量。约束为：
  q_bh>=0；chi_bh=0 时 q_bh=0；
  q_bh<=2*delta_h/3600；
  sum_{b:k(b)=k} q_bh<=4*delta_h/3600；
  sum_{b:k(b)=k,h} q_bh<=A_remaining,k。
初始 A=4 kWh；恢复使用快照实际剩余量。电池净增加为 0.90*q_bh。车辆不途中补电、不换电，不因驶过新道路弧重置 A。预算只有递减没有补充，所以上述总量约束与非负 q 可保证每个前缀不超预算；仍必须按时间输出前缀账本。

固定全序中的资源状态由事件增减量确定：
  每车司机容量1：DRIVE、G/P/R/U 开始 +1，结束 -1；
  每车起降通道容量1：L/R 开始 +1，结束 -1；
  每车机位容量2：R 开始预留 +1，L 结束释放 -1。
机体初始在车或正在 L 的机位、正在 R 的预留，以及快照中正在执行的司机/通道工作均进入 initial_occ。R 结束不再次加机位，P/READY 不释放机位，最终随车入库前不能提前清空机位。对最终入库之后的事件不安排该车新作业。

记区间 h 的计数为 occ_rh=initial_occ_r+sum_{rank(e)<=h} delta_resource(r,e)。通常要求 0<=occ_rh<=cap_r。若固定线性事件序仅因同刻开始/结束被排列成“先占后放”而出现 occ>cap，不得直接据此拒绝：应强制相应 delta_h=0。只在正长度区间禁止超过容量。因果边须保证每个正时长活动先开始后结束，并防止不属于初始活动的虚假释放；occ<0 表示结构/事件构造错误，直接拒绝。

最后入库电量 E_return,d 取实际承运车到库瞬间、仓库记账补满之前的值；出库机体入库时刻等于其最终承运车 F_k。令 z>=各出库机体入库时刻。未出库机体到库时刻为0、E_return=E_cap，不虚构任务。

完整成本使用第6章原口径，在线快照之前常量与之后变量拼接一次：
  C=c_km*(D_past+D_future)
    +wage_per_second*sum_k F_k_absolute
    +c_vehicle*(Qnet_past+eta_slot*sum_bh q_bh)
    +c_depot*sum_d(E_cap-E_return,d)，
  c_km=1.67693 元/km；
  c_vehicle=0.731012/(0.85*0.90) 元/净kWh；
  c_depot=0.731012/0.90 元/净kWh。
D 以 km 计。F 是从共同班次0开始的真实最终时刻；使用这项时不能再额外加一遍历史司机工时。Qnet_past 只含实际发生的车载净充电；仓库补满只做班次成本结算，不生成额外作业、充电时间或回库后再次出车。

第一次 LP 最小化 C。只有 status=0 且向量通过核验，才记其成本为 C_star、primary_complete=True；第二次加入 C<=C_star+1e-4 元，最小化 z。若第一阶段 status=1 但确有通过核验的可行向量，只能记其成本为 C_inc、primary_complete=False；预算允许时第二阶段可在 C<=C_inc+1e-4 内改进 z，但不能将 C_inc 称为成本最优值。没有已验证可行向量不进入第二阶段。不要用任意加权 C+epsilon*z 替代两阶段。第二阶段超时则保留已验证的最佳候选，标记 secondary_complete=False；只有两阶段都完成时才能称该固定子问题完成字典序优化。只要某阶段返回候选向量，都要检查约束残差和独立物理可行性后才能接收。

六、相邻至多 6 个事件重排的真实 MILP

调用者按下列固定轮转规则选窗口，不能自行改用另一套评分：每个重优化快照的 window_cursor 从0开始；对已有完整合法全序，取尚未执行的未来事件数 Nfuture，窗口长度 w=min(6,Nfuture)，枚举所有长度为 w 的连续未来窗口，过滤掉没有至少两个在强制先后 DAG 中互不可比事件的窗口，余下按起始 rank 升序排列。互不可比指 a 无有向路径到 b 且 b 无有向路径到 a，不能仅检查二者有没有直接边。若有 J 个窗口，选择下标 window_cursor mod J 的窗口，并将 cursor 加1；同一快照后续调用继续轮转，新的真实失败快照重置为0。若 Nfuture<2 或没有可动窗口则返回 NO_REORDERABLE_WINDOW。若没有完整合法 event_order，包括此前 ORDER_BUILD_FAILED，则返回 NO_EVENT_ORDER，不凭空调用局部 MIP。上述跳过均记日志，不计为求解器不可行。

由此得到窗口 ranks l,...,u，u-l+1<=6；只含尚未执行的边界事件。窗口外事件身份及顺序固定，所有未来时刻和充电量仍可重新优化。已承诺/正在执行动作的固定时刻、剩余时长、访问、几何、载荷和任务依赖保持约束；全局排序变化不是取消它们。接口 window_start 只能传入这一规则计算的起始 rank。

令 W 为窗口事件集合，R_W 为窗口位置。二元变量 y_er 表示事件 e∈W 占据位置 r∈R_W：
  sum_r y_er=1；sum_e y_er=1。
每个位置有连续时刻 tau_r∈[0,Tspan]，tau_r<=tau_(r+1)。事件变量 u_e 与选中位置联系：
  -Tspan*(1-y_er)<=u_e-tau_r<=Tspan*(1-y_er)。
窗口外 u_e=tau_rank(e)。这是有效 big-M，因为两者均在[0,Tspan]；不使用 10^6 之类无数据依据的大常数。

事件 rank 用 rho_e=sum_r r*y_er（窗口外是固定常数）。所有必须先后的不同事件对 a->b 都要求 rho_a+1<=rho_b；若属于同一物理事件则事先别名合并。原时间差、固定时长、几何、车辆轨迹、能量链和货物因果约束全部保留。这个模型重排的是事件身份，既非 LP 改名，也非在若干完整计划里择一。

定义事件已发生的前缀指示：
  F_eh=sum_{r<=h} y_er，当 e 在窗口内；
  F_eh=1[rank(e)<=h]，当 e 在窗口外。
对每个充电阶段 b 定义线性量
  chi_bh=F_(start_b),h-F_(end_b),h，0<=chi_bh<=1。
因阶段起止的 rank 先后关系，整数解中 chi_bh 恰为0或1；不用另设能乘上 delta 的未知充电比例。

保留 q_bh>=0，并用以下两条约束取代 chi*delta 的双线性乘积：
  q_bh<=2*(tau_(h+1)-tau_h)/3600；
  q_bh<=(2*Tspan/3600)*chi_bh。
卡车区间功率、累计交流预算、各自身充电阶段的电量链与第五部分相同。若 chi=0，q=0；若 chi=1，由第一条精确约束功率。这个线性化无需猜测未知充电量，也不会跨阶段借电。可删除始终chi=0的变量作稀疏化，但不得删去会随局部顺序变化而可用的项。

资源占用变为线性表达式：
  occ_rh=initial_occ_r+sum_e delta_resource(r,e)*F_eh。
同刻事件的任意排列可能产生零时间的临时超额，使用二元 z_h（只需为受窗口影响的间隔建立）处理：
  0<=occ_rh<=cap_r+M_occ,r*z_h；
  delta_h<=Tspan*(1-z_h)。
因此超额只可能发生在 delta_h=0；任何正时间间隔仍严格遵守容量。取 N_r=initial_occ_r+本后缀该资源所有正向占用事件增量之和，M_occ,r=max(0,N_r-cap_r)，这是该资源计数的有限上界。窗口外计数为常量，沿用第五部分的超额即 delta=0 规则。不允许使用任意巨大 M，也不允许用小正 epsilon 强制所有事件时间不同。

所有正时长资源活动具有各自开始/结束因果边，零间隔的 q 也被强制为0。求解后必须对所有同刻事件成组规范化：先保留真实因果边，再对可选拓扑节点以资源结束/释放优先，最后以稳定 event_id 排序。R_start 的槽预留、L_end 的槽释放、司机动作结束与下一动作开始都参与这一规则。不能为释放优先破坏 P_end 后才可 L_start、R_end 后才可 U_start、U_end 后才可 G_start 等因果关系。若同刻组不能得到合法拓扑顺序或独立资源回放失败，则该解不能接收。

局部 MILP 第一阶段最小化 C；若尚有调用时间和节点额度，约束 C<=当前整数 incumbent 成本+1e-4 后第二阶段最小化 z。只有第一阶段达到局部最优且第二阶段完成时，才能标记 local_lex_optimal=True；限时有解可以作为候选，但不得宣称局部最优。SciPy 不提供热启动，外部保留原已核验解；无新整数可行向量就原样返回该 incumbent。

从整数解提取并规范化全序后，必须调用一次 evaluate_structure(..., event_order=该序) 重解 LP 并独立核验。这次请求计入候选评价预算。最终用于接受判断的是回验后的 (C,z)，不是可能有残差的 MIP 原始目标。仅 MIP 窗口不可行不能证明固定结构所有排序不可行，更不能证明全恢复问题不可行。

七、新固定结构/几何的全序构造：禁止未定义“自动排好”

新候选没有可沿用的显式全序时，执行下列唯一流程：
1. 建立三部分给出的车辆、机体、货物流和冻结关系的强制先后 DAG。正时长活动开始指向结束；车访到达指向其人工动作开始、人工动作结束指向离开；道路离开指向下一到达；机体各相继阶段相连；R/U/P/G 的真实货物先后相连。对固定 lambda 能确定的时间关系也加边，例如 ROAD 的 dep<=Lend<=arr，以及由 lambda*D/v_T-10 的符号确定 Lstart 在 dep 前后；相等时只保留兼容真实因果的稳定次序。不要加入 Lstart 必须在同一道路弧的错误边。
2. 解参考时间 LP：保留所有固定几何、固定时长、冻结、访问包含、机体/车辆因果和 [0,Tspan] 时间约束，但暂不加电量、充电和司机/通道/机位互斥，目标最小化所有未来事件相对时刻之和，得到 t_ref。它只提供排序参考，不是完整可行计划。其不可行只能据模型说明固定结构/几何的这些必要条件不可行。
3. 对 DAG 做带资源检查的 Kahn 排序。初始化各资源为真实快照占用。每轮考虑入度为0且按事件增减量执行后不超出司机/通道/机位容量的事件；按 (t_ref，释放/结束优先级，稳定event_id) 选最小者，写入全序、更新资源和后继入度。对纯能量阶段边界不增加司机或通道占用。活动结束只能释放它自身真实持有的资源；不能释放别的无人机的槽位。初始在执行活动的结束由快照标记配对。
4. 若还有事件但没有可选节点，返回 ORDER_BUILD_FAILED。它表示这一确定性构序启发式未成功，外层仍可改结构、改位置或使用已存在候选上的局部重排；不得把该状态写成整个运营模型 INFEASIBLE。不能删依赖或临时增加机位继续。
5. 得到全序后，求解第五部分的两阶段 LP。参考 LP 的时间不是最终时间，等待和充电可以在完整 LP 内重新分配。若完整 LP 不可行，说明该结构、几何和这个顺序联合不可行，不说明其他顺序或其他 lambda 不可行。

这是一种确定性、受计算预算控制的初始排序规则，不是枚举所有全序的精确算法。局部 MILP 和外层 ALNS 都是扩展搜索的具体途径。MILP 的窗口最多6、连续搜索起点数及评价次数属于算法预算，不属于客户可接机范围、票数、航次数或业务可行域的上限。

八、结果合同与独立核验

Evaluation 至少包含 status、feasible、cost、last_drone_depot_s、event_order、schedule、各机阶段电量、q_bh交流与净电量、实际承运车账本、完整成本分解、solver_calls、wall_time_s、primary_complete、secondary_complete、violation_codes。没有可核验完整解时 cost/z 为 null，不用0或任意大罚数代替。

固定子问题的 LP 状态2可以记 LP_INFEASIBLE；状态1且没有验证可行向量记 EVALUATION_LIMIT；参考构序失败记 ORDER_BUILD_FAILED；约束残差/物理回放失败记 VALIDATION_FAILED。整体恢复仅在有对应全域证明时报告 INFEASIBLE；没有找到完整方案且预算耗尽用 NO_SOLUTION_LIMIT。

每个最终执行候选独立重算：L结束真实坐标；各段飞行距离/载荷；每次服务、等待、L/R耗电；车内真实充电资格及交流预算；同刻因果与资源释放/占用；异常批次R/U/G；每票保管者转移；所有出库机体客户R后随车入库；完整工时、道路费用和0.85/0.90补电成本。核验器不得调用 LP/MILP 的“feasible=True”作为物理证据。

9  完整求解器的核验要求

以下是完整模型的核验要求，不代表当前事件示例已验证路线、能耗和最优性：
1. 任一客户点均可成为接机访问，包括已服务、其他车所属及本次空送失败点。
2. 客户点外不能生成运营停车；放飞可在真实车辆轨迹的非客户位置发生。
3. 自动L可以与DRIVE重叠，P不在驾驶期间人工执行；P/L不再强制紧接。
4. 无人机独立飞行起点使用L完成的位置，不能错用提前10 s的位置。
5. 两个不同客户可在同一seed失效；首票、中票、末票、不同机均可遇到失败。
6. 失败集合按稳定客户/订单ID绑定，重排顺序、航次号和查询次数不改变该集合。
7. S/X共享隐藏环境；某一隐藏失败点改地送后不补抽另一个点。
8. 未实际观察故障的seed不删除；记录设置数量和实际触发数量。
9. 所有已失败且未交付票累积锁定地送，机上货物不消失，继续投递时载荷正确。
10. 第二次故障继承各自S/X真实状态，不能强行重置成相同快照。
11. 支持多票、多航次新增空送；接机容量与通道按实体冲突核验。
12. 同时到达事件先汇集当前已知信息，再生成一致恢复快照。
13. 真实几何、时序、电量、货物流和完整费用由独立检查器重算。
14. 十种子汇总保留负收益与不可行/未求得解状态，不伪造成本或平均收益。
15. 将“事件到点揭示”“虚拟时间即时决策”“真实在线计算耗时验证”分开报告。
16. 原地等待接机作为合法候选保留，所有等待按真实载荷计能耗；不重新增加固定120 s上限。
17. 同点恢复严格按R→U→G执行，车辆到场、无人机回收或卸货完成均不能提前记妥投。
18. 接机开始同时满足车到、机到、司机/通道/机位可用，所有重访均使用独立visit_id。
19. 正常60 s空送服务按释放包裹前载荷扣悬停能耗；失败不扣不存在的成功服务时间。
20. 简化等待能量上界为负时不得截断为0后判可行；一般路线逐段核算，不能借未来充电。
21. 一次回收带两票失败包裹时，动作/能源/车程只计一次，订单分类及各自响应时间分别记录。
22. 失败订单妥投后仍可保留历史标记，但不得继续出现在未完成需求中。
23. 嵌入数据包可解析、规范化哈希正确，六图数据与原始内容一致，单文件附录源码可完整提取。
24. 不将同点回收比例高、无跨车收益或负差值判为必然错误；先核验物理与统计口径，再解释参数和目标影响。
25. 在车且设备就绪时允许DRIVE期间充电；READY可充至L开始，本机P/L/R/U和离车状态充电为0，不因其他机作业而无条件停充。
26. 两机同时充电分别满足单槽及整车功率，累计扣实际承运车的交流余量；电池不超容量，不以未来充电掩盖当前欠电。
27. 返库路上实际充电计入Q_net及到库余电；并行驾驶与充电不重复计工时，不虚构行驶发电或供电预算刷新。

11  文献依据与适用边界

本节依据用户提供的11份PDF材料核对，其中A07为在线附录。以下页码均指PDF阅读器从文件第一页开始计算的物理页码，包含封面，不一定等于期刊印刷页码。文献用于说明相关建模选择，不将文献中的场景假设当作真实设备能力或本研究实验结果。

11.1  接机候选的文献依据

A01、A02、A03、A04、A06、A10和A11均采用客户或需求节点上的车机接驳，并将仓库作为相关起讫位置；这些模型允许不同程度的跨车回收。[A01-A04,A06,A10,A11] A05和A09在卡车实际访问的可达网络节点上实施同步，要求无人机到达或离开该节点时，卡车实际在场。[A05,A09] A07的示例也展示了无人机在不同编号节点之间由不同车辆放飞和回收。[A07]

因此，“全部客户地点具有接机候选资格，实际接机车辆必须到场”有直接的节点式协同建模参照。不过，部分文献进一步限制节点只能访问一次、无人机服务节点不能兼作起降点，或接机点必须属于当期卡车服务节点。本文针对突发交付失败，单独允许支援访问插入和已服务客户重访；这是本文的动态恢复设定，不能表述为上述文献均已支持任意支援重访。

11.2  道路会合节点、跨车回收与移动接机的区别

A08明确引入道路节点N_R，并与客户节点N_C组成网络；车辆在选中的节点与无人机同步。该文把卡车可达的道路网络节点视为可起降道路节点，是其模型假设，不代表真实城市所有道路节点均经过停车和接机条件验证。[A08] 道路节点可以是无客户需求的会合位置，不必建设固定场站，但它仍属于给定网络中的离散候选位置。

本文已经确定当前接机候选集合为全部客户点，不增加道路会合节点。A08仅作为将来具备路网和可停靠位置数据时的扩展参考，不进入当前基础算例或S/X主对照。

“跨车回收”改变接收无人机的车辆；“连续位置接机”改变接机位置的空间域；“移动接机”还改变接机时车辆的运动状态，三者不能混为一谈。A02把道路弧上离散起降点列为未来扩展；A11把行驶中起降列为未来研究。[A02,A11] 本文的沿车辆实际轨迹连续自动放飞，是明确列出的研究设备与作业假设，不能据这些文献直接宣称已有平台已经验证该能力。

11.3  本文故障定义与恢复动作的依据边界

本组材料未直接建立“到客户后才揭示空中交付不可用，而地面送达和车载回收保持可用”的随机故障机制。本文明确将失效对象限定为空中交付作业；机体仍能正常飞行，失败包裹仍在机上，客户地面可达，车辆停车后仍可接回无人机。因此，失效客户仍可成为接机点，是本文已经确定的故障与运营假设，不是由文献证明的普遍规律。

同点等车后回收并地送、主动飞往其他客户点接机、继续完成其他订单后接机，均属于本文允许比较的恢复安排。所有空中等待按实际载荷计能耗，车辆真实到场，回收、卸货交接和地送按规定顺序执行。部分文献允许无人机落地后无能耗等车，或忽略起降与换电时间；本文不直接套用这些简化。[A02,A04] 同样，不继承单票航次、禁止同点往返或一次访问等与本文已确定动态恢复范围冲突的限制，也不把故障限定为最后一航、最后一票。

12.4  固定数据结构与信息边界

至少定义以下类型：PublicInstance、PhysicalConfig、AlgorithmConfig、AlgorithmRandomStreams、PublicSnapshot、TruckVisit、DroneSortie、ScheduledAction、Plan、SolveResult、VerificationReport、EpisodeResult和ExperimentSummary。枚举名称可以按代码规范统一，但各类型必须具备明确字段和序列化格式。AlgorithmRandomStreams固定包含operator、destroy、accept三个Python random.Random对象，严格按7.11派生；不能用一个混合随机流替代，也不能从环境seed派生。

PublicSnapshot使用冻结数据类及不可变嵌套容器，与仿真内部状态不共享可变对象；仅做深复制而仍允许修改的普通字典不能作为最终公开接口。它至少含当前虚拟时间、已观察事件、已交付订单、强制地送且尚未交付订单、各包裹真实保管者、无人机机上清单、各机电量、实际承运车、车辆轨迹位置、各车剩余交流电量、不可撤销动作残段、保留的未来承诺和已发生成本前缀。每架无人机还须明确当前真实坐标、当前动作或飞行航段、已执行与剩余时间、当前飞行承诺以及P/L/R/U的进行阶段；重规划不得把进行中的机体重置到航段起点、客户节点或完整作业开始时刻。

公开快照不能含真实environment_seed、实现后的M、未揭示失败名单、私有环境引用、私有随机数状态或能反推出这些信息的运行编号。公开快照标识只根据公开内容规范化后计算。实验目录与审计记录可以保存环境seed，但其路径和私有元数据不得作为规划器输入。AlgorithmConfig不得直接持有整个包含私有实验实现的原始数据包。

恢复快照还须携带公开名义计划ID、由该计划冻结的H及公开重规划序号replan_index。H不能在第二次故障时按当前工作解重算；replan_index按实际公开重规划调用递增，用于7.11的算法随机流派生，不等于真实隐藏失败数M。

每张订单固定一个parcel_id，每架无人机固定一个drone_id。客户与包裹ID在各case内唯一，跨图汇总以(case_id, customer_id)或(case_id, parcel_id)为键；不同图重复使用c001、p001不是数据错误，不能为全局唯一而改动故障抽样所用原ID。同一客户重复访问产生新的visit_id，不能复用历史到离时刻。每次起飞产生flight_id，每次实际接机产生recovery_id。包裹保管者只能由真实P、成功空送、U或G事件改变；优化器修改候选计划不能直接改写现实保管者。

三个算法侧入口固定如下，其参数均不得包含隐藏环境：

  build_nominal(instance: PublicInstance, physical: PhysicalConfig,
                algorithm: AlgorithmConfig, rngs: AlgorithmRandomStreams,
                budget: SearchBudget)
                -> SolveResult

  solve_recovery(instance: PublicInstance, snapshot: PublicSnapshot,
                 remaining_plan: Plan, strategy: Strategy,
                 physical: PhysicalConfig, algorithm: AlgorithmConfig,
                 rngs: AlgorithmRandomStreams, budget: SearchBudget) -> SolveResult

  verify_plan(instance: PublicInstance, snapshot: PublicSnapshot,
              plan: Plan, strategy: Strategy, physical: PhysicalConfig)
              -> VerificationReport

实验层入口固定为：

  run_episode(instance, verified_nominal_plan, private_environment,
              strategy, algorithm_config, algorithm_seed) -> EpisodeResult

private_environment只交给仿真器和实验层。仿真器在实际空送到达时查询环境，形成Observation后才调用规划器；候选方案评价不得查询真实失败状态。每个回合关闭后，实验记录器才能取得完整隐藏名单用于审计。测试代码可构造有针对性的私有环境，但该接口只用于明确标识的测试夹具，不能替换正式六图的随机发生器。

12.5  固定命令行合同

以下命令和功能均须实现。命令示例中的路径是项目内相对路径；具体输入TXT位置由--spec给出，不硬编码当前对话的工作目录。

（1）提取完整数据与参考代码：
  python -m tdr extract --spec <完整TXT路径> --out data
读取两个JSON标记之间的内容及两个源码标记之间的内容。输出package.json、case_manifest.json、cases目录、固定运行配置，以及reference/dynamic_events_v3.py。验证原始对象的规范化哈希和源码字节哈希。不能根据说明文字重新手工录入450个客户，也不能擅自修改排序和ID编码。

（2）校验输入：
  python -m tdr validate --package data/package.json
检查六图名称、客户数量与唯一ID、坐标和质量有限值、单位、所有物理参数、算法配置必需项、标记与哈希，以及禁止在正式求解配置中启用本版不实现的算法。输出validation.json。输入错误必须给出字段路径及原因，不静默修正成另一套实例。

（3）生成名义计划：
  python -m tdr nominal --package data/package.json --case all --out outputs/nominal
为六张图分别生成一次无故障实现信息的名义计划，调用完整物理检查器，通过后保存计划、初始订单分配、末端时间、成本及H。十个环境及S/X复用同一份已核验计划。若某图未求得可行名义计划，保存具体状态，不得虚构H；与该计划关联的正式回合标为未启动并说明原因。

（4）执行一个环境下的S/X配对：
  python -m tdr simulate --package data/package.json --case C50 --environment-seed 1 --strategy both --nominal outputs/nominal/C50 --out outputs/single
从同一个私有失败集合和同一名义计划分别执行S/X。没有实际失效观察时也输出完整结果。--environment-seed仅在实验层使用，不能传入规划器。

（5）执行默认正式主实验：
  python -m tdr experiment --package data/package.json --nominal-dir outputs/nominal --formal --out outputs/formal
默认使用全部六图、环境seed=1,…,10、S/X两策略、算法基种子20261111，计划执行120个完整回合。--formal明确选择完整基础数据和默认预算；此命令禁止套用smoke_customer_limit=8，禁止改为只跑一个seed、只跑一种策略或只跑易解子集后称为正式实验。运行耗时较长时保存检查点并可续跑，不能删减实验矩阵。

（6）固定的算法随机性补充实验：
  python -m tdr experiment --package data/package.json --nominal-dir outputs/nominal --formal --stability --out outputs/stability
使用算法基种子20261111、20261112、20261113，每个环境分别运行三次，共360个S/X回合；所有重复继续使用主实验的同一名义计划。环境内重复先聚合，再做环境层配对统计。该命令用于稳定性检验，不把360回合说成360个独立故障场景，也不替代120回合主实验。

（7）执行小规模开发验收：
  python -m tdr smoke --package data/package.json --out outputs/smoke

（8）独立重放与检查结果：
  python -m tdr replay --episode-dir <一个已保存回合目录>
仅根据初始状态、实际动作和公开观察重放执行，独立重算物理状态与成本；记录器可在回合结束后另做私有审计匹配。重放不重新优化，也不重新随机生成失败以替换原回合。输出replay_verification.json，与原输出差异逐项列明。

批量运行增加--resume选项。仅当输入数据哈希、名义计划ID、完整配置和软件版本清单匹配时，才能跳过已经完成并核证的回合；未完成回合必须显式恢复或重跑。改变参数后不得继续混用原目录中的旧结果。

12.6  必须生成的输出

每张图的名义计划目录至少包含：nominal_plan.json、initial_assignment.json、config_snapshot.json、verification.json、cost.json、nominal_route.png和nominal_gantt.png。名义计划ID由公开计划及公开配置内容生成，不与隐藏环境绑定。

每个执行回合至少包含以下机器可读文件：
  run_metadata.json：case、策略、名义计划ID、环境seed、算法基种子、发生器版本、配置哈希及依赖版本。此文件归实验记录器，不作为规划器输入。
  public_events.jsonl：按虚拟时间记录执行事件和已经揭示的观察，不包含未揭示失败名单。
  private_world_audit.json：回合关闭后生成的完整私有审计，记录设置的失败数与名单；算法不读取此文件。
  actions.csv：实际动作ID、主体、位置/轨迹段、开始结束时刻、前后载荷、电量和资源占用。
  parcel_ledger.csv：每票真实持有者变更、空送观察、卸货交接、最终妥投方式及时间。
  charging_ledger.csv：实际承运车、DRIVE/STOP状态、充电区间、交流输出、净入电量和车辆供电余额。
  recovery_ledger.csv：recovery_id、flight_id、实际放飞车/接机车、客户/visit_id、R/U时刻及机上未交付票。
  drone_terminal.csv：末次客户点回收、最终承运车、随车入库时刻、return_mode及仓库补电前余电。
  replans.jsonl：每次公开快照标识、求解状态、总耗时、模块耗时、计数、最好可行解变化、局部子问题状态和证明范围。
  cost.json：完整成本分项及能量守恒校验，无法形成完整方案时总班次成本为null，已经发生的前缀成本另列。
  result.json：是否完整执行、是否核证、实际观察数量、各求解/执行状态、最终成本及说明。
  verification.json：独立检查结果与具体违反约束列表，包含实体和时刻以便定位。

12.7  状态与错误处理合同

求解器状态使用OPTIMAL、FEASIBLE_LIMIT、INFEASIBLE、NO_SOLUTION_LIMIT、INVALID_INPUT、ERROR。只有对所声明问题范围具有相应证明时，才能报告OPTIMAL或INFEASIBLE。局部MILP最优、局部事件窗口无解、坐标搜索停止，均不能升级为原完整模型的全局结论。局部状态单独记录在replans.jsonl中。

执行层另设episode_status：COMPLETED_VERIFIED、STOPPED_NO_FEASIBLE_SUFFIX、INVALID_EXECUTION、NOT_STARTED_INVALID_NOMINAL、ERROR。NO_OBSERVED_AIR_FAILURE是观察情况标记，不代替求解或执行状态。

若发生失败后在预算内没有找到完整核验后缀，停止本回合的方案执行并保存当时真实前缀，状态为STOPPED_NO_FEASIBLE_SUFFIX；不得让无人机免费悬停到结束，不得直飞仓库，不得丢弃机上货物，也不得把未完成客户算作妥投。停止仿真表示算法没有提供可执行恢复，不表示现实无人机已安全完成任务。完整成本和返库时刻为null，前缀费用及未完成实体单独保留。

若独立检查器发现违反物理约束，记录INVALID_EXECUTION或ERROR及详细原因，不把该候选当成有效结果。超时、数值问题和模型不可行分别记录；异常不能被吞掉后返回零成本。批量实验可继续运行其他预定回合，但最终返回非成功状态并给出失败清单，不能只汇总成功回合后宣布全部完成。

12.8  测试与验收清单

测试针对真实业务行为，不以“函数能返回”“文件已生成”替代约束核验。至少覆盖以下验收组，使用明确标记的人工小实例计算预期结果；不得为了让正式实验出现收益而修改正式随机环境。

A. 数据与信息边界：完整450客户无遗漏；规范化数据和源码哈希正确；稳定ID及发生器版本不变；相同case与环境seed产生相同私有名单；重复到达事件幂等；同刻观察合并；两种不同隐藏世界在公开历史相同时，规划器输入和同算法随机状态下的决策相同。最后一项使用固定评价/节点预算的确定性测试模式，锁定输入顺序和依赖版本，不启用墙钟停止；不得用两次60s运行因机器调度造成的不同搜索长度误判信息泄漏。

B. 多票与多次失效：真实执行至少一条三票无人机航次，分别测试首票、中票和末票失败；失败票仍在机上，其他票可继续或返回；测试两票失败发生于同一无人机和不同无人机；第二次恢复继承第一阶段电量、保管者和历史成本；已地送完成的失败票不再派送。

C. 回收与货物流：所有客户点具有接机资格，包括失效、已服务、其他车负责的客户；同点R→U→G按实体顺序执行；异点接机后由真实接收车地送；同一实体回收携两张失败票时能源及动作只计一次；S禁止受影响航次跨车，X允许但不强制；支援访问和重访不重复产生需求。

D. 能量与充电：按每段真实载荷计算巡航、成功服务、L/R和等待耗电；失败不释放货物，也不扣不存在的成功服务；原地等待上界为负时不可行；不足余电不能用未来充电弥补；允许DRIVE及合法STOP内充电，READY可充至L开始，本机P/L/R/U及离车阶段不得充电；跨车后扣真实接收车的4 kWh交流预算，不能重置电量或共享虚拟能源池。

E. 位置与资源：至少一例放飞位置严格位于道路弧内部，使用L结束坐标计算首段飞行；L允许与DRIVE并行，P/G/R/U不能与本车驾驶重叠；两机争用单起降通道时必须排队；回收开始预留机位且占位+预留≤2；每次客户重访具有独立visit_id。测试初始位置或某个lambda不可行但同一弧其他位置可行的情形，禁止将单点失败误判为整条弧非法。

F. 终端与成本：正常、异常和最后一航均先在客户点接回，再由实际承运车载回；空载也不得直飞仓库；未起飞机体不虚构R；无人机入库时刻等于最终承运车到库时刻；末段实际充电计入到库余电。0.85/0.90/0.90只按原成本与物理定义使用，4 kWh交流预算不再额外乘0.85；仓库补电不增加本班次动作或再次出库；两种电费表达式与能量守恒一致，司机工时不重复计算并行动作。

G. 求解器与范围：LP/MILP变量、激活条件和局部最优范围符合第7章；局部MILP只操作最多6个允许重排的相邻未执行事件，不能自行改变坐标、货物保管者、航段清单或载荷；连续搜索按真实距离核验；为每个固定算子提供至少一个实际调用且能形成合法非空候选的测试，不能是返回原计划的空壳；无可行初解和时限中止状态正确；保存最好已核验可行方案，未核验的最后候选不能覆盖它。时间受限运行不要求逐字节重现，但测试模式使用固定评价预算、固定种子和稳定排序核对确定性；正式运行记录实际评价次数与求解版本。

H. 端到端：从本TXT提取数据，安装项目，运行pytest、smoke、六图nominal，再执行完整主实验和独立replay。检查120个预定回合均有结果或明确的未启动/停止状态，未观察失败的环境不补抽、不删除。某些名义计划采用全地送、或正式环境未观察到失败，都不能替代B至G组针对性故障、真实多票航次和跨车恢复测试。正式统计只使用有真实有限核证成本的配对，n_pair为0或1时按正文规则返回null统计量；环境和算法重复不混为独立样本。

所有验收应实际运行并保存命令、退出码、测试数量与结果文件。合理的无解或算法时限中止可以作为研究结果保留，但不能用来掩盖软件缺陷；必须先排除输入错误、约束漏实现和核验失败。正式实验若因环境限制不能全部执行，要如实交付可续跑检查点及未运行清单，不得把未运行回合填成已完成。

"""1—2个客户订单随机失效、运行中揭示：Python 3.10+标准库示例。

    python dynamic_events_v3.py --seed 1
    python dynamic_events_v3.py --seed-summary
    python dynamic_events_v3.py --self-test

默认从全部具备空送资格的客户订单中抽样，包括名义地送订单。候选数>=2
时，失效点数在{1,2}中等概率选择，再无放回选择客户；0/1个候选分别设
0/1个失效点。这是研究情景分配，不是实测故障率。

隐藏结果绑定稳定的客户/包裹ID，不绑定名义航次、到达序号或搜索调用。
两策略使用相同case_id和环境seed即可面对同一外生环境；路线分化后，
各自在实际到达时观察。如果某个隐藏失效订单直接地送，就不产生该次
空送失败，也不补抽新点。设置失效点数和实际观察失败数分别报告。

规划器仅收到不可变的公开状态与已发生观察，不接收环境对象、环境seed、
未来失效集合或未来修复时间。Python双下划线仅提供封装；完整系统仍应
使用白名单消息/进程接口隔离未来信息。回合关闭后才返回独立审计信息。

演示从两架已载货的在途机和两件车上地送货物开始，回放人工事件夹具。
失败票保持在机上并累计ground_required；其他包裹可继续配送。未优化
S/X，未计算距离、能耗、回收、放飞位置或最终成本，也未证明物理可行。
--seed-summary只统计十个环境的事件表现，不是十种子的恢复成本实验。

class HiddenFailureEnvironment:
    """环境私有场景固定；观察次数和访问顺序不会改变失效客户。"""

    def __init__(self, orders: tuple[Order, ...], case_id: str, seed: int):
        if len({o.parcel_id for o in orders}) != len(orders):
            raise ValueError("包裹ID必须唯一。")
        if len({o.customer_id for o in orders}) != len(orders):
            raise ValueError("本例按一客一件建模，客户ID必须唯一。")
        self.__orders = {o.parcel_id: o for o in orders}
        eligible = sorted((o for o in orders if o.air_eligible),
                          key=lambda o: (o.customer_id, o.parcel_id))
        encoded = json.dumps([GENERATOR_VERSION, case_id, seed],
                             ensure_ascii=False, separators=(",", ":")).encode("utf-8")
        derived_seed = int.from_bytes(hashlib.sha256(encoded).digest(), "big")
        rng = random.Random(derived_seed)
        count = rng.choice((1, 2)) if len(eligible) >= 2 else len(eligible)
        self.__failed = frozenset(o.parcel_id for o in rng.sample(eligible, count))
        self.__eligible_count = len(eligible)
        self.__case_id = case_id
        self.__seed = seed
        self.__observed_failures: set[str] = set()
        self.__arrivals: dict[str, Observation] = {}
        self.__closed = False

    def observe_air_arrival(self, parcel_id: str, now_s: float,
                            attempt_id: str) -> Observation:
        if self.__closed:
            raise RuntimeError("回合已经关闭，不能继续访问该环境。")
        if attempt_id in self.__arrivals:
            old = self.__arrivals[attempt_id]
            if old.parcel_id != parcel_id:
                raise ValueError("同一到达事件ID不能对应不同包裹。")
            return old
        order = self.__orders[parcel_id]
        if not order.air_eligible:
            raise ValueError("静态不具备空送资格的订单不能被派作空送。")
        failed = parcel_id in self.__failed
        observation = Observation(
            now_s, "DELIVERY_UNAVAILABLE" if failed else "AIR_DELIVERY_ACCEPTED",
            parcel_id, order.customer_id, not failed,
        )
        if failed:
            self.__observed_failures.add(parcel_id)
        self.__arrivals[attempt_id] = observation
        return observation

    def finish_episode(self) -> EpisodeAudit:
        """由实验执行器关闭回合后调用；返回值绝不能再发给规划器。"""
        if self.__closed:
            raise RuntimeError("回合审计已取回，不重复结束。")
        self.__closed = True
        note = ("候选>=2，M在{1,2}中等概率；客户无放回抽样。"
                if self.__eligible_count >= 2 else
                "候选不足2个，M等于候选数量；没有强造故障。")
        return EpisodeAudit(
            self.__case_id, self.__seed, GENERATOR_VERSION, platform.python_version(),
            "ALL_AIR_ELIGIBLE_CUSTOMERS_INCLUDING_NOMINAL_GROUND",
            self.__eligible_count, len(self.__failed), tuple(sorted(self.__failed)),
            tuple(sorted(self.__observed_failures)), note,
        )

def _run_fixture(orders: tuple[Order, ...], actions: tuple[Action, ...],
                 environment: HiddenFailureEnvironment) -> DemoResult:
    """回放给定动作；失败后继续脚本只为验证事件，不代表安全恢复策略。"""
    parcels: dict[str, PublicParcel] = {}
    for order in orders:
        action = next((a for a in actions if a.parcel_id == order.parcel_id), None)
        holder = (("drone:" if action.mode == "AIR" else "truck:") + action.actor_id
                  if action is not None else "truck:t1")
        parcels[order.parcel_id] = PublicParcel(
            order.parcel_id, order.customer_id, order.mass_kg, holder, order.air_eligible,
        )
    planner = RecoveryPlanner()  # 无环境、种子或隐藏失效集合参数。
    # 货物清空不等于实体飞机消失，空载机仍保留在公开状态中。
    known_drone_ids = sorted({action.actor_id for action in actions if action.mode == "AIR"})

    def publish(now_s: float, observations: tuple[Observation, ...]) -> None:
        drones = tuple(PublicDrone(
            drone_id,
            tuple(sorted(p.parcel_id for p in parcels.values()
                         if p.holder == "drone:" + drone_id)),
            sum(p.mass_kg for p in parcels.values() if p.holder == "drone:" + drone_id),
        ) for drone_id in known_drone_ids)
        planner.on_observation(PlannerInput(
            now_s, observations, tuple(parcels[key] for key in sorted(parcels)), drones,
            tuple(sorted(p.parcel_id for p in parcels.values() if p.ground_required)),
        ))

    publish(0.0, ())
    queue: list[tuple[float, int, str, str, str]] = []
    for i, action in enumerate(actions):
        heapq.heappush(queue, (action.time_s, 1, f"a{i:03d}", action.mode,
                               action.parcel_id))

    while queue:
        now_s = queue[0][0]
        same_time = []
        while queue and queue[0][0] == now_s:
            same_time.append(heapq.heappop(queue))
        observations = []
        # 同刻先处理完成事件，再处理全部到达，最后只发布一次公开快照。
        for _, _, action_id, mode, parcel_id in sorted(same_time):
            parcel = parcels[parcel_id]
            if mode == "AIR":
                if parcel.delivered or parcel.ground_required:
                    raise ValueError("不能重复空送已完成或已知需要地送的包裹。")
                if not parcel.holder.startswith("drone:"):
                    raise ValueError("空送包裹必须实际在无人机上。")
                observation = environment.observe_air_arrival(parcel_id, now_s, action_id)
                observations.append(observation)
                if observation.kind == "DELIVERY_UNAVAILABLE":
                    parcels[parcel_id] = replace(parcel, air_eligible=False,
                                                 ground_required=True)
                else:
                    heapq.heappush(queue, (now_s + 60.0, 0, action_id + "_done",
                                          "AIR_COMPLETE", parcel_id))
            elif mode == "AIR_COMPLETE":
                if parcel.delivered or parcel.ground_required:
                    raise ValueError("失败票不能被登记为成功空送。")
                parcels[parcel_id] = replace(parcel, holder="delivered", delivered=True)
                observations.append(Observation(now_s, "AIR_DELIVERED", parcel_id,
                                                 parcel.customer_id, True))
            elif mode == "GROUND":
                if parcel.delivered or not parcel.holder.startswith("truck:"):
                    raise ValueError("地送开始前必须由车辆实际持货且尚未交付。")
                # 地送不查询隐藏空送状态，不能透露尚未观察到的失效客户。
                heapq.heappush(queue, (now_s + 50.0, 0, action_id + "_done",
                                      "GROUND_COMPLETE", parcel_id))
                observations.append(Observation(now_s, "GROUND_SERVICE_STARTED", parcel_id,
                                                 parcel.customer_id, None))
            elif mode == "GROUND_COMPLETE":
                parcels[parcel_id] = replace(parcel, holder="delivered", delivered=True)
                observations.append(Observation(now_s, "GROUND_DELIVERED", parcel_id,
                                                 parcel.customer_id, None))
            else:
                raise ValueError("未知人工事件类型。")
        publish(now_s, tuple(observations))

    # 审计只交给外层记录器；规划器从来没有拿到这些字段。
    audit = environment.finish_episode()
    return DemoResult(tuple(planner.transcript), tuple(planner.requests), audit)


def run_demo(seed: int, case_id: str = "DEMO10") -> DemoResult:
    orders = example_orders()
    return _run_fixture(orders, example_actions(),
                        HiddenFailureEnvironment(orders, case_id, seed))


class DynamicEventTests(unittest.TestCase):
    @classmethod
    def setUpClass(cls):
        # 定位有针对性的边界测试夹具，不是正式实验选种子或筛收益。
        wanted = {frozenset(x) for x in (("p001", "p002"), ("p001", "p005"),
                                        ("p009", "p010"), ("p003",), ("p004",))}
        cls.seeds: dict[frozenset[str], int] = {}
        for seed in range(10000):
            audit = HiddenFailureEnvironment(example_orders(), "DEMO10", seed).finish_episode()
            key = frozenset(audit.hidden_failure_parcels)
            if key in wanted:
                cls.seeds.setdefault(key, seed)
            if len(cls.seeds) == len(wanted):
                break
        if len(cls.seeds) != len(wanted):
            raise AssertionError("未找到测试所需的事件夹具。")

    def test_same_seed_reproduces_environment_and_public_history(self):
        self.assertEqual(run_demo(1), run_demo(1))

    def test_sampling_has_one_or_two_distinct_customers_including_ground_orders(self):
        audits = [HiddenFailureEnvironment(example_orders(), "DEMO10", seed).finish_episode()
                  for seed in range(256)]
        self.assertEqual({a.configured_failure_count for a in audits}, {1, 2})
        self.assertEqual({p for a in audits for p in a.hidden_failure_parcels},
                         {o.parcel_id for o in example_orders()})
        for audit in audits:
            self.assertEqual(len(set(audit.hidden_failure_parcels)), audit.configured_failure_count)

    def test_candidate_shortages_are_explicit(self):
        empty = HiddenFailureEnvironment((), "EMPTY", 1).finish_episode()
        one = HiddenFailureEnvironment(example_orders()[:1], "ONE", 1).finish_episode()
        self.assertEqual(empty.configured_failure_count, 0)
        self.assertEqual(one.configured_failure_count, 1)

    def test_input_order_does_not_change_failure_environment(self):
        orders = example_orders()
        left = HiddenFailureEnvironment(orders, "DEMO10", 18).finish_episode()
        right = HiddenFailureEnvironment(tuple(reversed(orders)), "DEMO10", 18).finish_episode()
        self.assertEqual(left, right)

    def test_different_strategy_visit_orders_share_customer_outcomes(self):
        orders = example_orders()
        s_world = HiddenFailureEnvironment(orders, "PAIRED", 4)
        x_world = HiddenFailureEnvironment(orders, "PAIRED", 4)
        s_outcomes = {o.parcel_id: s_world.observe_air_arrival(o.parcel_id, i * 10.0,
                                                              f"S{i}").air_delivery_available
                      for i, o in enumerate(orders)}
        x_outcomes = {o.parcel_id: x_world.observe_air_arrival(o.parcel_id, i * 15.0,
                                                              f"X{i}").air_delivery_available
                      for i, o in enumerate(reversed(orders))}
        self.assertEqual(s_outcomes, x_outcomes)
        self.assertEqual(s_world.finish_episode().hidden_failure_parcels,
                         x_world.finish_episode().hidden_failure_parcels)

    def test_latent_ground_failures_are_not_observed_or_replaced(self):
        result = run_demo(self.seeds[frozenset(("p009", "p010"))])
        self.assertEqual(result.audit_after_episode.configured_failure_count, 2)
        self.assertEqual(result.audit_after_episode.observed_air_failure_parcels, ())
        self.assertEqual(result.replan_requests, ())
        self.assertTrue(all(p.delivered for p in result.public_transcript[-1].parcels))

    def test_second_failure_accumulates_without_losing_first_failed_parcel(self):
        result = run_demo(self.seeds[frozenset(("p001", "p002"))])
        self.assertEqual(len(result.replan_requests), 2)
        last = result.replan_requests[-1]
        self.assertEqual(last.all_known_ground_required, ("p001", "p002"))
        parcels = {p.parcel_id: p for p in result.public_transcript[-1].parcels}
        for key in ("p001", "p002"):
            self.assertFalse(parcels[key].delivered)
            self.assertEqual(parcels[key].holder, "drone:d1")
        self.assertTrue(parcels["p003"].delivered)
        self.assertTrue(parcels["p004"].delivered)

    def test_failures_can_affect_two_different_drones(self):
        result = run_demo(self.seeds[frozenset(("p001", "p005"))])
        last = {d.drone_id: d.manifest for d in result.public_transcript[-1].drones}
        self.assertEqual(last, {"d1": ("p001",), "d2": ("p005",)})

    def test_same_time_observations_are_merged_before_replanning(self):
        seed = self.seeds[frozenset(("p001", "p005"))]
        orders = example_orders()
        actions = (Action(100.0, "AIR", "p001", "d1"),
                   Action(100.0, "AIR", "p005", "d2"))
        result = _run_fixture(orders, actions, HiddenFailureEnvironment(orders, "DEMO10", seed))
        self.assertEqual(len(result.replan_requests), 1)
        self.assertEqual(result.replan_requests[0].newly_failed_parcels, ("p001", "p005"))

    def test_different_hidden_futures_have_identical_earlier_public_inputs(self):
        first = run_demo(self.seeds[frozenset(("p003",))])
        second = run_demo(self.seeds[frozenset(("p004",))])
        before = lambda result: tuple(s for s in result.public_transcript if s.time_s < 300.0)
        self.assertGreater(len(before(first)), 3)
        self.assertEqual(before(first), before(second))

    def test_public_inputs_contain_no_future_failures_or_environment_seed(self):
        result = run_demo(20261111)
        forbidden = {"seed", "environment_seed", "hidden_failure_parcels", "environment",
                     "configured_failure_count", "rng", "audit_after_episode"}

        def inspect(value):
            if isinstance(value, dict):
                self.assertTrue(forbidden.isdisjoint(value))
                for child in value.values():
                    inspect(child)
            elif isinstance(value, (tuple, list)):
                for child in value:
                    inspect(child)

        for state in result.public_transcript:
            inspect(asdict(state))

    def test_delivery_failure_does_not_disable_truck_recovery(self):
        result = run_demo(self.seeds[frozenset(("p001", "p002"))])
        failures = [o for s in result.public_transcript for o in s.observations
                    if o.kind == "DELIVERY_UNAVAILABLE"]
        self.assertTrue(failures)
        self.assertTrue(all(o.ground_delivery_available and o.truck_recovery_available
                            for o in failures))

    def test_observation_uses_actual_arrival_and_duplicate_query_is_idempotent(self):
        world = HiddenFailureEnvironment(example_orders(), "DEMO10", 3)
        first = world.observe_air_arrival("p001", 127.0, "actual_1")
        repeated = world.observe_air_arrival("p001", 999.0, "actual_1")
        self.assertEqual(first, repeated)
        self.assertEqual(first.time_s, 127.0)

    def test_episode_audit_closes_future_observation_access(self):
        world = HiddenFailureEnvironment(example_orders(), "DEMO10", 1)
        world.finish_episode()
        with self.assertRaises(RuntimeError):
            world.observe_air_arrival("p001", 100.0, "late_call")


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    parser.add_argument("--seed", type=int, default=20261111)
    parser.add_argument("--seed-summary", action="store_true",
                        help="只汇总种子1—10的环境及观察数量，不运行S/X优化。")
    parser.add_argument("--json", action="store_true", help="公开事件记录及回合结束后的独立审计JSON。")
    parser.add_argument("--self-test", action="store_true")
    args = parser.parse_args(argv)
    if args.self_test:
        suite = unittest.defaultTestLoader.loadTestsFromTestCase(DynamicEventTests)
        result = unittest.TextTestRunner(verbosity=2).run(suite)
        return 0 if result.wasSuccessful() else 1
    if args.seed_summary:
        records = [run_demo(seed) for seed in range(1, 11)]
        if args.json:
            print(json.dumps({"scope": "十个环境的事件统计，不是S/X成本实验", "records": [
                {"seed": r.audit_after_episode.environment_seed,
                 "configured_failure_count": r.audit_after_episode.configured_failure_count,
                 "hidden_failure_parcels": r.audit_after_episode.hidden_failure_parcels,
                 "observed_air_failure_parcels": r.audit_after_episode.observed_air_failure_parcels}
                for r in records]}, ensure_ascii=False, indent=2))
        else:
            print("仅统计人工夹具的十个随机环境；未求解S/X、未计算平均成本差。")
            print("seed  设置点数  实际观察数  回合结束后审计的失效票    已观察失败票")
            for record in records:
                audit = record.audit_after_episode
                print(f"{audit.environment_seed:4d}  {audit.configured_failure_count:8d}  "
                      f"{len(audit.observed_air_failure_parcels):10d}  "
                      f"{','.join(audit.hidden_failure_parcels):22s}  "
                      f"{','.join(audit.observed_air_failure_parcels) or '无'}")
            print("原地送的隐藏失效客户不会触发空送失败，程序不会为凑数重新抽样。")
        return 0

    result = run_demo(args.seed)
    if args.json:
        print(json.dumps(asdict(result), ensure_ascii=False, indent=2))
        return 0
    print(result.scope)
    print("两机在途载货，8票按示意空送事件回放，另2票地送；全部10票均可被抽为失效点。")
    print("规划器输入不含未来失效集合和环境seed；下列记录按到达/服务时刻揭示。")
    labels = {"DELIVERY_UNAVAILABLE": "到点发现不能空送，货物留机，立即触发重排",
              "AIR_DELIVERY_ACCEPTED": "到点正常，开始60秒空中交付",
              "AIR_DELIVERED": "空中交付完成",
              "GROUND_SERVICE_STARTED": "开始50秒地送服务，不查询空送失效信息",
              "GROUND_DELIVERED": "地面交付完成"}
    for state in result.public_transcript:
        for observation in state.observations:
            print(f"t={state.time_s:6.1f}s  {observation.parcel_id}  {labels[observation.kind]}")
    final_state = result.public_transcript[-1]
    print("\n累计已知必须地送的包裹：", ",".join(final_state.ground_required_parcels) or "无")
    print("本示例没有执行回收优化，失败货物仍保留在真实机体上：")
    for drone in final_state.drones:
        print(f"  {drone.drone_id}: {','.join(drone.manifest)}，载荷{drone.payload_kg:g}kg")
    audit = result.audit_after_episode
    print("回合结束后的环境审计（从未传入规划器）：")
    print(f"  设置{audit.configured_failure_count}个失效点，实际观察"
          f"{len(audit.observed_air_failure_parcels)}个空送失败。")
    print("  失效票：", ",".join(audit.hidden_failure_parcels))
    print("  环境seed：", audit.environment_seed)
    print("没有回收成本、S/X收益或实际在线控制性能结论。")
    return 0


if __name__ == "__main__":
