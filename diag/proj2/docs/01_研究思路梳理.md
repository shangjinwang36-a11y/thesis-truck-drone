# 研究思路梳理：无人机随机空中交付失效后的车机协同恢复

> 依据：《无人机随机空中交付失效_V6_1_Codex完整实施规范_20261111.txt》（V6.1）
> 本文把 TXT 中的“场景—模型—算法—实验—交付”五层逻辑重新组织成一条可执行的研发路线，并标明本实现的范围与简化。

---

## 1. 一句话概括

在“5 卡车 + 5 无人机、全部客户点可停车接机、无人机可沿车辆实际轨迹连续自动放飞、允许行驶充电、无人机必须在客户点被回收后随车返库”的配送系统中，**每张图随机隐藏 1—2 个客户的空中交付失效**；失效只在无人机真实到达客户时才揭示，失败票留在机上、锁定地送。研究比较两种回收政策：

- **S（same-truck）**：受影响的在途航次只能回收到本航次原放飞车；
- **X（cross-truck）**：可回收到班次内任一合格车辆。

其余规则完全相同。目标是**全班真实成本**（车辆里程 + 司机工时 + 车载充电 + 仓库补电），并报告可行性、回收分类、等待与响应时间。

## 2. 研究问题（可检验的假设）

| 编号 | 问题 | 度量 |
|---|---|---|
| RQ1 | 跨车回收（X）是否降低全班成本？ | 配对差 Δ_s = C_S,s − C_X,s（10 个环境种子） |
| RQ2 | 收益是否稳定？ | 差值均值/标准差/极值/正负零计数/近似置信区间 |
| RQ3 | 恢复动作如何发生？ | 同点/异点 × 原车/跨车 两层统计、实际观察失败数、空中等待时间与能耗 |
| RQ4 | 路径与环境如何改变？ | 实际车程相对名义计划的差值、最后入库时间、失败票响应时长 |
| RQ5 | 算法模块是否有效？（补充实验） | 消融：uniform_weights / no_coordinate_polish / no_local_mip |

关键认识（TXT 第 5.2 节）：**不能保证每个种子的 X 成本都更低**。X 的可行域包含 S 的可行域只在“同一已知状态、同一确定性子问题”下成立；两次未知故障会把两策略带到不同状态，因此逐 seed 差值可正可负，必须全部保留。

## 3. 场景与业务规则（建模前提）

### 3.1 资源
- 5 辆卡车，5 架同型无人机（唯一编号）；每车出库携带 1 架，每车最多 2 个机位。
- 每车 1 条车载起降作业通道；司机人工动作 G/P/R/U 串行，自动放飞 L 可与驾驶并行。
- 客户一客一件、不拆分；单航次总载荷 ≤ 30 kg；卡车包裹容量不约束。

### 3.2 位置与时间
- 全部客户点都是**停车接机候选**（包括失效客户、已服务客户、其他车负责的客户）；允许支援重访，每次访问独立 `visit_id`。
- 客户点以外不设运营停车点；但**放飞点可沿车辆实际轨迹连续选择**（道路弧上参数 λ∈[0,1]）。
- 设 V 为客户点集合，V_stop = V，V_recovery = V；仓库只是班次起终点，不做中转/接机/无人机独立降落。
- 若车辆在弧 i→j 上、离开 i 的时刻为 v_i：
  - `x_L = (1−λ)x_i + λx_j`，`t_L = v_i + λD_ij/v_T`，`s_L = t_L − τ_L`；
  - 无人机首段飞行必须从 **L 结束位置**起算，不能误用 L 开始前 10 s 的位置。

### 3.3 作业链
- 人工准备 P=30 s（装货、在客户停车访问或出库仓库完成）；
- 自动放飞 L=10 s（可与驾驶重叠，不占司机时间）；
- 空中成功交付服务 60 s（释放包裹后才减载）；
- 动力回收 R=30 s；异常卸货交接 U=20 s（一次异常回收按批计一次）；地面交付 G=50 s；
- 同点恢复实体顺序严格为 `AIRBORNE_WAIT → R → U → G`，车到、机落、卸货都不等于妥投。

### 3.4 失效环境
- 候选总体 = 本图**全部**有空中交付资格的客户订单（当前六图全部客户），按 `(customer_id, parcel_id)` 排序后抽样；
- M ~ Uniform{1,2}（候选 ≥2 时）；无放回抽 M 个客户；
- 环境种子 = SHA256(紧凑 UTF-8 JSON `[generator_version, case_id, environment_seed]`) 的无符号大端整数；发生器版本 `customer-failure-v3-1`；
- 失效**只在无人机真实到达该客户时**揭示；若该客户被改为地送，则不产生观察；允许实际观察数为 0/1/2，不补抽、不删 seed；
- 规划器只能看到公开快照（已观察事件、真实状态、冻结残段、剩余需求、已发生费用），**不能**看到环境 seed、M、未来失败名单。

### 3.5 能量与充电
- `R_cal(m) = 28000 − 400m`（m∈[0,30] kg）；
- `E_fly(l,m) = β_cruise · E_cap · l / R_cal(m)`；
- `P_h(m) = β_hover·[P0 + (P30−P0)m/30]`，`P0=E_cap/(29/60)`，`P30=E_cap/(18/60)`；
- 电池 3.9688 kWh，回收余电下限 `E_min = 0.39688 kWh`；
- 每槽交流 2 kW、整车 4 kW、机槽效率 0.90；每车出库 4 kWh 交流预算；不换电、不途中补电、不刷新预算；
- **在车且设备就绪即可充电**（行驶、合法停车、返库路段均可）；本机 P/L/R/U、离车、空中阶段不充电；READY_ON_TRUCK 可一直充到本机 L 开始；
- 充电是**有约束的可选决策**：成本上 `c_vehicle=0.95557 > c_depot=0.81224` 元/净 kWh，故最优往往只补必要电量，返库纯行驶段通常不再充电。

### 3.6 班次与成本
- 名义计划固定后：`H = max_k F_k_nominal + 1800 s`，所有交付、接机、返库须 ≤ H；H 不能因第二次故障延长；
- `c_km = 8.57×14.9/100 + 0.40 = 1.67693 元/km`；
- `C_elec = c_vehicle·Q_net + c_depot·Σ_d(E_cap − E_return,d)`；
- `C_res = c_km·全班车程(km) + C_elec + w_s·Σ_k F_k`，`w_s = (105976/2088)/3600` 元/s；
- 目标字典序：先 min C_res，再在 1e-4 元容差内 min 全班最晚机体入库时刻 z。

## 4. 数学模型（优化口径）

### 4.1 集合与参数
- 客户 i∈C（|C|=50/100），包裹 p∈P（一客一件），车辆 k∈K（5），无人机 d∈D（5）；
- 客户访问 v∈V_k（含重复访问），航次/架次 s∈S_d；
- 参数：坐标、质量 m_p、速度、作业时长、能耗系数、电池、充电功率与效率、成本系数、班次界 H。

### 4.2 决策
1. 车辆层：每车有序访问链、每次访问的 G/P/R/U 动作；
2. 无人机层：机体—航次链、实际承运车、放飞轨迹段与连续位置 λ、空送顺序、回收车辆与客户访问、机上余货处理；
3. 依赖层：货物流（保管者变更）、机体流、人工/通道/机位占用、充电资格事件、时间。

### 4.3 关键约束
- **交付唯一性**：每票恰好由一次 G 或一次成功空送完成；失败票不得空送妥投；
- **载荷**：每航次装载 ≤30 kg；每飞行航段载荷 = 机上全部未卸货物（含已失败未交接票）；
- **时间**：车辆相邻访问 `t_arr(w)=t_dep(v)+D_vw/v_T`；人工动作完整落在停车访问内；L 结束位置由实际轨迹给出；
- **回收同步**：`s_R ≥ max(t_arr_truck, t_arr_drone)`，`f_R ≤ t_dep`；异常时 `s_U ≥ f_R`、`f_U ≤ t_dep`；`s_G ≥ f_U`；
- **资源**：司机容量 1、起降通道容量 1、每车机位（占位+预留）≤2；同刻事件按因果/释放优先规范化；
- **能量**：逐阶段端点电量 0≤E≤E_cap；每次 R 结束 E≥E_min；不得用未来充电掩盖当前欠电；
- **终端**：每个出飞航次必须在客户点 R；机体由实际承运车随车返库；`t_return(d)=T_depot(final_carrier)`；未出飞机体不虚构 R；
- **策略**：S 的受影响航次 rec_truck=launch_truck；X 任意合格在班车。

### 4.4 目标
```
min C_res = c_km·Σ_k L_k/1000 + c_vehicle·Q_net + c_depot·Σ_d(E_cap−E_return,d) + w_s·Σ_k F_k
s.t.  lexicographic: min C_res, then min z = max_d t_return(d) within 1e-4 CNY
```
（S/X 比较的是该目标的真实实现成本，不是期望成本；不可行/未求得解不得填 0。）

## 5. 算法：事件触发的车机协同恢复 ALNS 数学启发式（tdr_alns_v61）

### 5.1 总体框架
```
名义阶段（不读隐藏环境）:
  ① 五车全地送初解（角度扇区 + 最近邻）→ 前向计算 C_ground、T_bound_nominal
  ② 空送转换启动阶段（每车单票/双票必做；再轮流加票）
  ③ 固定 ALNS：6 移除 × 2 修复 + SA + 5 几何起点 + 坐标细化 + 局部事件重排 MILP
  ④ 独立核验 → 固定名义计划 & H

执行阶段（逐环境种子）:
  仿真推进真实轨迹 → 无人机到点查询隐藏环境 → 观察合并 → 截断快照
  → 恢复 ALNS（热启动：保留合法回收承诺、删除失败服务、枚举余票子集）
  → 核验 → 执行真实后缀 → 下一次失效（若有）→ 继承真实状态再规划
```

### 5.2 搜索组件（固定，不做算法菜单）
| 组件 | 内容 |
|---|---|
| 移除 | D1 RANDOM_DEPENDENCY、D2 AFFECTED_SORTIE、D3 RENDEZVOUS_RESOURCE、D4 ENERGY_CHAIN、D5 SUPPORT_VISIT、D6 SORTIE_REGROUP；q=min(N_adj,max(1,ceil(r·N_adj)))，r~U(0.10,0.30) |
| 修复 | R1 全局最小代理增量贪心；R2 regret-2；目录惰性生成、候选 64/批、扫描 512、稳定 ID 轮转游标 |
| 代理分数 | `Ĉ = c_km·L_T/1000 + w_s·(L_T/v_T+50n_G+30n_P+30n_R+20n_U) + c_depot·E_air_no_wait` |
| 接受 | 模拟退火；`T0=−0.01·max(C_init−C_prefix,1)/ln0.5`，`T(p)=T0·0.01^p`；只对真实成本劣化生效 |
| 权重 | 每 25 轮 `w←max(0.1,0.8w+0.2·s/n)`；奖励 33/9/3/0 |
| 连续位置 | 5 个基础向量 B0…B4（继承 λ/0/1/0.25/0.75/0.5 补足）+ 最多 40 次坐标步长细化（h=0.25 减半至 1e-3） |
| 局部 MILP | 每 25 轮或停滞 ≥20 轮、距上次 ≥5 轮触发；只重排最多 6 个相邻未执行事件；回验 1 次完整评价 |
| 预算 | 名义 1000 次完整评价；恢复 60 s 墙钟（末 2 s 保留核验）；确定性计数模式每次恢复 1000 次评价；max_search_rounds=2000 |

### 5.3 评价入口
`evaluate_structure(state, structure, λ, event_order, context)`：固定结构下求完整时序、能量、充电与成本；返回状态/成本/z/计划/计数；**任何进入入口的候选都计 1 次评价**。独立核验器必须重算后才允许写入最好解/工作解。

### 5.4 信息隔离与随机数
- 规划器接口不接收 environment_seed / M / 隐藏名单；公开快照不可变；
- 算法随机流三个独立流：`operator / destroy / accept`；派生
  `seed = SHA256("tdr_v61|base_seed|case_id|phase|replan_index|stream_name")[:8]`（大端），
  公式不含 strategy、environment_seed。

## 6. 实验设计

### 6.1 主实验（120 回合）
- 六图：C50、R50、RC50、C100、R100、RC100（共 450 客户，454.5 kg）；
- 每图 1 份**经核验的共同名义计划**，10 个环境种子（1…10）共用；
- 每 seed 执行 S/X 两策略（共享同一隐藏失败集合、物理参数、成本口径、H 与预算）；
- 算法基种子 20261111；比较 `Δ_s = C_S,s − C_X,s`；
- 统计：均值、标准差、min/max、正/零/负计数、n_pair、近似 95% CI（n≥2 时）；所有状态保留；
- 补充实验（命令保留）：稳定性 3 个算法基种子 × 60 环境 = 360 回合；消融 4 配置 × 120 = 480 回合。

### 6.2 指标
- 回合：`episode_status`、实际观察失败数/设置失败数、S/X 成本、工时、车程、耗电、最后入库时间、核验状态；
- 恢复动作层（recovery_id）：launch_truck / recovery_truck / 客户 / visit / R-U 时刻 / 机上未交付票；
- 失败订单层（parcel_id）：同点/异点 × 原车/跨车、首次失败时刻、卸货/地送时刻、响应时长；
- 资源：空中等待时间与能耗、回收余电、失败票妥投时长、全班车程相对名义计划的差值。

### 6.3 六类图形
1. 名义路线图（五车轨迹 + 无人机航段）；
2. 名义甘特图（车辆访问/作业/充电 + 无人机阶段）；

## 7. 本实现的边界与简化（诚实声明）

为在本次交付中形成**可运行、可核验、可复现**的第一版，本项目按 V6.1 的物理与业务规则实现，但对求解器的部分内部模块做了工程化简化，正式论文使用前应逐项替换/补强：

| 规范要求 | 本实现 | 影响 |
|---|---|---|
| 全局事件序 LP（参考时间 LP + 成本 LP + z LP，三阶段） | 采用**前向确定性调度 + 固定点迭代**求时序，再用**分阶段充电 LP**（HiGHS）求最小充电量与能量可行性；成本为真实口径 | 时序取“最早可行”，不保证全局时间最优；成本仍按真实公式核算 |
| 最多 6 事件局部 MILP（HiGHS） | 实现**局部事件重排枚举**（窗口内 R/U/G/P/L 顺序 + 同刻释放优先），仍回验完整评价 | 局部邻域更小，非 MILP 最优 |
| 6 移除 × 2 修复的完整依赖闭包 | 实现 6 类移除与 2 类修复，闭包按“订单—航次—访问—动作”依赖实现；候选目录用游标轮转 | 算子实现较规范简化 |
| 连续位置 5 起点 + 坐标细化 | 实现 5 起点 + 逐维 ±h 坐标模式搜索（h 减半至 1e-3，40 次上限） | 与规范一致 |
| 60 s 恢复预算 | 主实验若按 60 s 将耗时数小时，本次先跑**缩减预算开发版**并记录覆盖配置；同时保留 60 s 预算命令 | 结果标注“开发预算运行”，不冒充正式 60 s 结果 |
| 全事件类型/快照冻结 | 实现卡车访问、P/L/R/U/G、充电、能量、回收、返库；简化跨车后的机位细节 | 物理主约束均进入核验 |

**声明**：本实现不声称已经产生 V6.1 定义的“正式六图十种子实验结果”；所有运行均记录实际预算、版本与配置哈希，结果仅作为方法与代码的可运行性证据。若正式论文使用，应按 60 s 预算重跑并复核。
